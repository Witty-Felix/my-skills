# 升级草案 · 视觉皮完全隔离（v3.3.0-a）

> 状态：**草案，未实施**。目标版本 **v3.3.0**，与在制的 Style Contract / 两张新皮合并发布。
> 一句话：把「视觉皮之间可以互相借东西」这条隐含默契，改成**白纸黑字的硬隔离 + 可执行检查**。
> 适用范围：`pop-collage`、`cartoon-mascot` 两张**全规格皮**。`award-gold` 已在制、签名独立，另案；18 种 catalog 半规格皮不动（见 §8）。

## 1 为什么要做

不是「这次画得不像」，是**规则本身允许了混用**。三处硬证据：

### 1.1 两皮的「手势四件套」是同一配方，只换了常数

| 要素 | `pop-collage` | `cartoon-mascot` | 判定 |
|---|---|---|---|
| 描边 | `border:3px solid ink` | `border:3px solid ink` | **完全相同** |
| 投影 | `box-shadow:8px 8px 0`（分级 4 / 7–9 / 12–14） | `box-shadow:6px 6px 0` | 同语法，差 2px |
| 旋转 | `rotate(-2deg)`，±4° 内 | `rotate(-1.6deg~2.1deg)` | 同语法，差 0.4° |
| 圆角 | 未定义（≈0–3px） | `border-radius:4px` | 近似 |

四件套里有三项是**同一句话换了数字**。肉眼看不出 6px 与 8px 的差别，但看得出「一个硬边方块斜着摆、底下垫一块实心黑影」——这就是用户说的「像其他样式」。

### 1.2 `cartoon-mascot` 的规格明文鼓励跨皮复用

`cartoon-mascot.md` §5 原文：

> **手势纪律（跨角色通用）**：卡片一律 `3px solid var(--cm-ink)` + `rotate(-1.6°~2.1°)` 微旋转；阴影一律 `box-shadow:6px 6px 0 var(--cm-ink)` 实心无模糊。

「跨角色通用」四个字把这条规则定性成**跨皮资产**，于是它天然可以被任何角色皮继承——`pop-collage` 就是它的上游。规则自己写着「通用」，执行层就没有理由隔离。

### 1.3 `pop-collage` 的组件清单把引擎类和私有类混在一张表里

`pop-collage.md` §7「通用件」表：

| 类名 | 真实性质 |
|---|---|
| `.hd` `.kick` `.ttl` `.note` | **引擎结构类**（契约 §二 明列为公共契约） |
| `.dots` `.stk` | 风格私有类，但**无 `pc-` 前缀** |

后果有两层：① 私有类无前缀，跨皮复制必然撞名；② 引擎类和私有类共处「通用件」标题下，读起来像「这些都是大家共用的」，把隔离边界从文档层面抹掉了。

## 2 隔离原则（四层，从上到下收紧）

| 层 | 名字 | 共用？ | 管什么 | 违反后果 |
|---|---|---|---|---|
| **L0** | 机制层 | ✅ 必须共用 | token 三层（E/S/F）、`<id>-` 前缀、`<id>/assets` 与 `<id>/fonts` 目录、引擎结构类、`<script>` 与 HUD 结构 | 引擎崩、跨皮污染 |
| **L1** | 组件词表 | ❌ 互斥 | 每皮的 `.xx-*` 类名是**闭集**，只在本皮内有效；新类必须先在皮规格 §7 登记 | 未登记类 = 混用 |
| **L2** | 视觉签名 | ❌ 互斥 | 六要素指纹，见 §3；**强隔离项任意一项相同即判混用** | 两皮趋同 |
| **L3** | 版式与装置 | ❌ 互斥 | 背景装置只做衬底；页面结构只能取自本皮 §8 页面原型表 | 装置当版式用 |

> L0 是唯一允许「一样」的层。**除了 L0，任何两层之间都不许出现相同的视觉决定。**

## 3 签名表（L2 的判定依据）

### 3.1 六要素与强弱

| # | 要素 | 强度 | 说明 |
|---|---|---|---|
| 1 | 描边结构 | **强** | 单线 / 双线包边 / 无描边 |
| 2 | 投影方式 | **强** | 实心偏移影 / 零影 / 柔影 / 内阴影 |
| 3 | 强调载体 | **强** | 斜贴标签 / 白底旁白框 / 深色块反白标题 |
| 4 | 旋转 | 弱 | 允许微旋 / 禁止旋转 |
| 5 | 圆角 | 弱 | 直角 / 两级圆角 / 大圆角 |
| 6 | 纹理 | 弱 | 半调网点 / 集中线 / 纸纹 / 无 |

> **为什么第 3 项从「旋转」换成「强调载体」**：三张皮并存后，`cartoon-mascot` 与 `soft-sticker` 同为「禁旋转」，二元强项立刻失效。旋转是**有无型**要素，皮一多就撞；强调载体是**选择型**要素，每张皮必然不同。选强项的判据是「在皮的数量增长时还能不能区分」，不是「看起来像不像」。

**判定规则**：① 六要素至少 5 项不同；② **强隔离项（1/2/3）任意一项相同 → 直接判混用**，不再看其余。

### 3.2 现状 vs 目标

| 要素 | `pop-collage`（保持，独占） | `cartoon-mascot` | `soft-sticker`（新增） |
|---|---|---|---|
| 描边 | 单线 3px | 双线包边 3+2+1.5 | **无描边（0px）** |
| 投影 | 实心偏移 `8px 8px 0` | 零影 | **柔影 `0 6px 18px rgba(63,70,113,.14)`** |
| 强调载体 | 斜贴标签 `.stk` | 白底旁白框 | **深色块 + 反白标题** |
| 旋转 | `-2°`（±4°） | 0° | 0° |
| 圆角 | ≤3px | 0 | 8 / 16 两级 |
| 纹理 | 半调网点 10px | 集中线 | 无 |

**结论：三强项全冲突，`cartoon-mascot` 必须换签名。**

### 3.3 `cartoon-mascot` 新签名的 CSS 配方

```css
/* ① 双线包边（替代单线墨边） */
.cm-frame{
  border:3px solid var(--cm-ink);
  box-shadow:inset 0 0 0 2px var(--cm-paper), inset 0 0 0 3.5px var(--cm-ink);
}
/* ② 零偏移影：层次靠分格白缝与暗部，不靠投影 */
/* ③ 禁旋转：任何 rotate() 都视为违规 */
/* ④ 直角 */
border-radius:0;
/* ⑤ 集中线（漫画放射线）：只用于情绪页与强调块，一页至多一处 */
.cm-burst{background:repeating-conic-gradient(from 0deg at 50% 50%,
  var(--cm-ink) 0deg 0.6deg, transparent 0.6deg 6deg);opacity:.16}
/* ⑥ 对白框（替代斜贴标签） */
.cm-say{position:relative;background:var(--cm-paper);border:3px solid var(--cm-ink);border-radius:0;
  padding:10px 16px;font:800 16px/1.6 var(--cm-font-body)}
.cm-say::after{content:"";position:absolute;left:26px;bottom:-12px;width:0;height:0;
  border:7px solid transparent;border-top:10px solid var(--cm-ink)}
```

配套代价（必须一起改）：
- `.cm-card` 去掉 `box-shadow` 与 `border-radius:4px`
- `.cm-tag` 退役，改由 `.cm-say` 承担强调；确需标签的场景改用「序号块」（白底墨边 + 0 旋转）
- `.cm-hero-frame` 的 `rotate(2deg)` 与 11px 实心影一并去掉，改双线包边
- 封面 `★` 的 `text-shadow:2px 2px 0` 也要去（那是偏移影的变体）

## 4 借用禁令（黑名单）

写进每张皮的 §0，逐条禁止：

1. **禁引用他皮类名**：`cartoon-mascot` 页面不得出现 `.pc-*` / `.ag-*` / `.stk` / `.dots`；反之亦然。
2. **禁引用他皮 token**：`cartoon-mascot` 的 `:root` 不得出现 `--pc-*` / `--ag-*`。
3. **禁复用他皮的签名配方**：哪怕改了数值（把 8px 改成 6px、把 -2° 改成 -1.6°）也算复用——**改数值不是隔离**，这条是本次事故的直接教训。
4. **禁跨皮借资产**：不得引用 `visual-library/assets/` 根目录（该目录已冻结，仅供 pop-collage），一律走 `<id>/assets/`。
5. **禁把装置当版式**：背景装置只做衬底，不得用来分栏、分区、承载信息结构（J-29）。
6. **禁现场造类**：组件词表是闭集，新类先登记进皮规格 §7 再使用。

## 5 机械检查（让「严格不混用」有牙）

新增 `deckcore/scripts/lint_skin.py`，Step 4 自检必跑，**exit 非 0 即停**。

| 编号 | 检查 | 判定 | 适用 |
|---|---|---|---|
| R1 | 裸 HEX | `:root` 外出现 `#RRGGBB`（`@font-face` src、图片路径除外）→ fail | 全部 |
| R2 | 未登记类 | 页面里的 `.xx-*` 不在皮规格 §7 白名单 → fail | 全部 |
| R3 | 跨皮类名 | 出现 `<他皮id>-` 前缀的类 → fail | 全部 |
| R4 | 跨皮 token | `:root` 出现 `<他皮id>-` 前缀的变量 → fail | 全部 |
| R5 | 签名违规 | 按皮加载禁列正则，命中即 fail | 每股一份 |
| R6 | 共享资产 | `<img src>` 指向 `visual-library/assets/` 根 → fail | 全部 |

`cartoon-mascot` 的 R5 禁列（正则）：

```
box-shadow:[^;}]*[1-9]\d*px\s+[1-9]\d*px\s+0     # 偏移影
transform:[^;}]*rotate\(\s*-?[1-9]                  # 非零旋转
border-radius:\s*(?!50%)[1-9]                       # 非直角（50% 圆形图标不判违规）
background-image:[^;}]*radial-gradient[^;}]*1\.\dpx # 半调网点（pop 独占）
```

`pop-collage` 的 R5 禁列：

```
box-shadow:inset 0 0 0                                     # 双线包边（cm 独占）
border-radius:\s*(1[0-9]|[2-9]\d)px                        # 大圆角
repeating-conic-gradient                                   # 集中线（cm 独占）
```

用法：

```bash
python deckcore/scripts/lint_skin.py --skin cartoon-mascot "<项目>-放映页.html"
# 任何一条 fail 都打印：规则号 / 行号 / 命中片段 / 期望
```

> R5 是本次草案的核心产出：**它把「别混」从审美判断变成字符串匹配**。没有它，规则会在一周内退化回口头约定。

# 附则 A · 单调判定标准

> 起因：14 页整稿交付后，用户指着四页（基准四卡 / 四场景 / 六档阶梯 / 夜间）说「这些板块会很单调」。
> 这四页不是画错了，是**在标准层面缺了一条**：隔离草案只管「像不像这张皮」，没管「这一页有没有东西可看」。
> 本附则补上这一轴。它是**判据**，不是形容词表——每条都能被量或被指出来。

---

## A.1 复盘：那四页到底哪儿单调

把当时的页面拆开看，六条同时命中：

| # | 症状 | 当时的具体情形 | 为什么眼睛会觉得空 |
|---|---|---|---|
| 1 | **同构元素超过 3 个** | 四张 263×356 的白卡，圆角、阴影、内边距完全一致，只有两行字不同 | 四个一模一样的框排一行 = 一个「列表」，扫描时没有落点 |
| 2 | **元素载荷率过低** | 卡片面积 93,628 px²，文字实际占约 12,000 px² ≈ **13%** | 剩下的 87% 不是留白，是没有内容的面积 |
| 3 | **缺大面积视觉块** | 整页最大元素是 263×356 的卡，占画面 10.2%；没有任何东西超过 15% | 视觉重心散成四个小点，画面「平」 |
| 4 | **明度跨度不足** | 浅蓝底 + 四张白卡，全在 85–100 明度区间；没有深色块 | 没有对比就没有节奏，看着像没上色 |
| 5 | **页面节奏雷同** | 05、11 两页都是「顶部标题 + 一行卡」，间隔不到 6 页重复一次 | 翻页时没有「换气」，累积成单调 |
| 6 | **主体缺席** | 四页里三页完全没有角色，一页角色在角落 | 这张皮的辨识度本来就靠角色承担，角色不在，只剩方块 |

修复后对照（同一批页）：卡底补头肩图 → 载荷率 13% → **约 42%**；六档页给柱子开洞 → 出现「洞径递增」这条可读的线索；夜间页补躺姿 → 最大元素从 10.2% 提到 18%。

## A.2 七条判据（可测，按优先级）

### ① 三秒测试（不可量化，但最准）
首次看到这一页，**三秒内能不能说出「这页在讲哪一个东西」**。
说不出来 → 这一页没有主体，直接判单调，不必再看其余六条。

### ② 遮主体测试（判断「留白」还是「空洞」）
把页面上的角色/主图遮住，剩下的内容**还能不能被理解**。
- 还能理解 → 说明主体只是装饰，页面的真实结构是「文字块」→ **空洞**。
- 不能理解 → 主体承担了语义 → 是**留白**，通过。

> 这条是本次复盘里最有用的一条。四卡页遮住角色后依然完全读得懂，所以它是空洞，不是留白。

### ③ 载荷率（元素内被占用的面积比）
`载荷率 = 元素内文字/图的实际边界面积 ÷ 元素总面积`
- **阈值 ≥ 25%**；低于 25% 必须补图，或把元素缩小到接近内容。
- 卡片类元素最容易踩：263×356 的卡里只放两行字 = 13%，必判不合格。

### ④ 同构元素上限
同页「同类 + 同尺寸 + 同样式」的元素 **≤ 3 个**。
第 4 个起必须制造差异：换底色（白→深）、换尺寸、或把其中一个换成图。
> 四卡页天然违反这条（4 个），所以四卡页必须默认「一张卡换色」或「一张卡换图」。

### ⑤ 面积层级
每页至少一个视觉块面积 **≥ 画面 15%**（1280×720 即 ≥ 138,240 px²，约 480×288），且这类大块 **≤ 2 个**。
- 没有大块 → 画面平。
- 超过 2 个 → 互相抢，重心不明。

### ⑥ 明度跨度
每页至少出现 **两档明度**：浅底（明度 85–100）与深块（明度 25–45）。
全浅底的页 **不得连续超过 2 页**——第 3 页必须落一个深色块或满版深色。

### ⑦ 构图不重复
连续 **3 页**不得使用同一栅格（例如连续三页都是「顶部标题 + 一行卡」）。
重装置页（画格墙 / 满版深色）连续不超过 2 页，之后必须跟 1 页轻页。

---

## A.3 机器能测的部分

三条能脚本化，其余靠人眼。建议并入 `lint_skin.py` 的第二组规则（`--monotony`）：

| 编号 | 检查 | 判定 |
|---|---|---|
| M1 | 同页同尺寸元素计数 | `.ss-card` 或同等尺寸的块 ≥ 4 → 警告「需差异化」 |
| M2 | 最大元素面积占比 | 全页最大定位块 < 15% 画面 → 警告「缺大面积视觉块」 |
| M3 | 连续页明度 | 连续 3 页无 `--board` 深色块 → 警告「节奏过平」 |

无法脚本化的：① 三秒测试、② 遮主体测试、③ 载荷率（要先知道内容边界）。这三条只能人工过。

## A.4 落到执行：Step 4 出页时加一道「单调自检」

写完一批页，在截图回查之前先过这一张表：

```
□ 每页三秒内说得出主体？
□ 遮住主体后页面还读得懂吗？（读得懂 = 空洞，要重排）
□ 每张卡的载荷率 ≥ 25%？
□ 同页同构元素 ≤ 3 个？超过的做了差异化？
□ 每页有 ≥15% 面积的大块？且不超过 2 个？
□ 每 3 页至少有 1 页出现深色块？
□ 连续 3 页没有重复同一栅格？
```

七条里挂 2 条以上 → 这一页判单调，回到版式层重排，**不许靠加装饰抢救**。

---

## A.5 一句话

> **单调不是「不好看」，是「这一页没有主体」。**
> 留白围着主体才叫留白，围着空气就叫空洞——判据只有一句：遮住主体，页面还成立吗。

# 附则 B · 位置关系判定标准

> 起因：14 页定稿后复查，音符与齿轮悬在纯背景里、枕头与角色之间留着缝、结尾页角色压住 HUD。
> 这四处不是画得不好，是**从来没有一条规则规定过「谁挨着谁、挨多近、谁压谁」**——元素都在，相互关系没人管。
> 附则 A 管「这一页有没有主体」，本附则管「主体与文字怎么共存」。两条合起来，一页才算成立。
> 与 A 一样：**这是判据，不是形容词表**，每条都要能被量、被指出来。

## B.1 复盘：四处到底哪儿错了

把四处并排看，同一类错误换了四种外表：

| # | 症状 | 当时的情形（真实坐标） | 为什么眼睛会读错 | 违反 |
|---|---|---|---|---|
| 1 | **道具悬空** | 02 音符 `left:700 top:404`，左边是正文、右边是圆环，它落在两者之间的空档里 | 不在任何「面」上，读成掉在桌上的一枚贴纸 | ③ 承载 |
| 2 | **无承托面** | 07 齿轮 `left:900 top:472`，在最后一级柱基右下的空白处 | 与柱基没有任何对齐或接触，读成页面装饰 | ③ 承载 |
| 3 | **该接触却没接触** | 11 枕头 `right:352 bottom:150`，与角色可见轮廓之间留着一段缝，两者**零重叠** | 两件东西并排 = 没有「枕」这个动作，只有「两个素材」 | ③ 接触 |
| 4 | **压进禁区** | 13 角色 `right:132 bottom:-54`，包围盒与右下 `190×44` 禁区相交 | 脸与手被页码条压住，读成裁切事故而非破框 | ④ Z 序 |

## B.2 六条判据（可测，按优先级）

### ① 落点测试（一票判定，与 A.2② 同源）
遮住这张贴纸，页面**有没有任何变化**。
- 有变化 → 它承担语义，通过。
- 毫无变化 → 它没有落点，**删掉或挪位**，不许用「放这儿好看」辩护。

> 与 A.2② 的区别：A 问「遮住主体，页面还读得懂吗」（判整页空洞）；B 问「遮住这张贴纸，页面有变化吗」（判单个元素有没有落点）。一个查页，一个查件。

### ② 净距与禁区（一票否决）
| 关系 | 最小净距 |
|---|---|
| 贴纸 ↔ 正文 | **24px** |
| 贴纸 ↔ 标题 | **32px** |
| 贴纸 ↔ 页码 / 图注 | 16px |
| 卡内头肩图 ↔ 卡内边距 | 底对齐、左右居中、高度 ≤ 卡高 45% |

两条零容忍：
- **压字** = 0 分，不管构图多好看。
- **压脸**（道具挡住角色的眼—嘴矩形）= 0 分，角色失去表情就等于失去动作。

### ③ 三型关系，三套距离
贴纸与页面的关系只允许三种。**答不出是哪种，就是没落点。**

| 型 | 定义 | 阈值 | 典型道具 |
|---|---|---|---|
| **承载** | 压在一条既有水平边上（卡沿 / 块沿 / 基线 / 页底） | 间隙 **0**，且承托边本身可见 | 水杯、枕头、尺子、书 |
| **关联** | 不接触，语义指向主体 | 距角色头部 **≤120px**，且在**视线朝向那一侧** | 音符、问号、星星、喇叭 |
| **接触** | 与角色互相碰 | 间隙 **≤24px**，或重叠 **5–20%** | 抱着的耳机、扶着的杯子 |

> 重叠 >20% 是遮挡，<5% 是分离——**只有 5–20% 读成「碰着」**。11 页的枕头就是调进这个区间才成立。

### ④ Z 序四层，不可越级
| 层 | z-index | 成员 |
|---|---|---|
| L1 底 | 0 | 背景色、画格墙、薄纱 |
| L2 承托 | 2–4 | 深色块、白卡、顶条、结句条、虚线框 |
| L3 贴纸 | 5–9 | 角色、道具 |
| L4 引擎 | 70 / 80 | 讲稿抽屉、HUD |

- **L3 恒压 L2**。唯一例外是刻意的「藏在卡后」：z 降到 1，但**必须露出 ≥60% 的头部**。
- **L4 是文字禁区**：右下 `190×44` 与讲稿抽屉内不得有字。角色躯干可以延伸到其后（破底时无法避免），但**脸与手必须在其外**。
- 道具要压住角色的一部分时，**压躯干不压脸**（枕头压后脑、杯子压手边）。

### ⑤ 破框唯一
- 一页**只允许一处**破框（四边合计按边计）。
- 裁切线必须穿过**躯干**（页面高度的 45–75% 区间），不许穿脸、不许穿手。
- 破框后仍须看到 **≥60% 的头部**。

### ⑥ 锚点对齐
贴纸的水平锚点优先落在栅格线：**72 / 363 / 654 / 945 / 1208**，允许 **±8px** 视觉修正。
不许出现「差 5px 谁都看不出、但就是歪着」的位置——那种位置在投影仪上会被放大成「不整齐」。

## B.3 机器能测的部分

六条里五条能脚本化。建议作为 `lint_skin.py` 的第三组规则（`--position`），与 A 的 `--monotony` 并列：

| 编号 | 检查 | 判定 |
|---|---|---|
| P1 | 落点 | 贴纸框到最近 L2 元素 / 纸边的最小距离 > 24px，且未破框 → fail |
| P2 | 压字 | 贴纸框 ∩ 任意文本节点框，相交面积 > 0 → fail |
| P3 | 压脸 | 道具框 ∩ 角色脸部框（图高上 45%、水平中 60%）→ fail |
| P4 | 禁区 | 文本框 ∩ 右下 `190×44`；角色脸 / 手 ∩ 同区 → fail |
| P5 | 破框 | 越出 section 的贴纸计次 > 1 → fail；裁切线落在头部框 → fail |
| P6 | 锚点 | 贴纸 `left/right` 解析值不在栅格 ±8 → 警告 |

实现方式（无需新增依赖）：

```bash
# 页面内注入测量脚本，把结论写进 <body data-lint="P1:0;P2:0;...">
google-chrome --headless=new --dump-dom --virtual-time-budget=1500 \
  "file://$PWD/<项目>-放映页.html?lint=1" > /tmp/dom.html
grep -o 'data-lint="[^"]*"' /tmp/dom.html
```

两个前提，本包都满足：
1. 舞台是固定 `1280×720`，`getBoundingClientRect()` 直接可比，不需要缩放换算；
2. 贴纸 PNG 已按 alpha 裁到可见边（`crop(getbbox())`），所以 **DOM 框 ≈ 可见框**，pixel bbox 可用。

> 状态诚实标注：**P 组与 A 的 M 组一样，目前只有设计、尚未落地**。`lint_skin.py` 现在只有 R 组（签名隔离）。三组一起实现，才算这把尺真正带上刻度。

## B.4 落到执行：Step 4 出页时加一道「位置自检」

与 A.4 的单调自检同一道关口，**排在截图回查之前**：

```
□ 遮住它，页面有变化吗？（没有 = 没落点）
□ 它压字了吗？压脸了吗？（压了 = 0 分）
□ 它是承载 / 关联 / 接触？三型都答不出 = 挪位
□ 它压的是该压的那层吗？（L3 压 L2，不反）
□ 破框只有一处？裁切线在躯干、头还露 60%？
□ 右下 190×44 里没有字、没有脸、没有手？
```

**挂一问即重排**，不是"记下来下次注意"。

## B.5 一句话

> **贴纸不是「摆在那儿」，是「搭在那儿」。**
> 元素之间的关系只有三种：压着、挨着、看着。三种都答不出，它就不该出现在这一页。
