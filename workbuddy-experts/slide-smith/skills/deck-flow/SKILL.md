# 汇报演示工作流

四个门，三道审核。**跳过任何一个门，这次产出就是废的。**

```
┌─ Step 1 收料 ────────► 需求简报.md          （不用审，问清即可）
├─ Step 2 出大纲 ──────► <项目名>-大纲.html      ⛔ 必须等「通过」
├─ Step 3 出逐页 ──────► <项目名>-逐页内容.html  ⛔ 必须等「通过」
└─ Step 4 出页面 ──────► 视觉皮（开选型页 → 卡片 A 岔路 → 岔 B 才问谁出图）→ 定配图层级 → 三页样张 ⛔ 等「满意」→ 铺开 → 放映页.html / 演示稿.pptx
```

工作目录：`<workspace>/ppt/<中文项目名>/`。**所有产出文件一律中文命名**，同放一处，永不分散（见 J-27）。

| 阶段 | 文件名 | 说明 |
|---|---|---|
| Step 1 | `需求简报.md` | 收料结果 |
| Step 2 | `<项目名>-大纲.html` | 审阅载体，浏览器直接打开 |
| Step 3 | `<项目名>-逐页内容.html` | 审阅载体，同上 |
| Step 4 样张 | `<项目名>-样张三页.html` / `.pptx` | 只做前三页，等确认满意 |
| Step 4 成品 | `<项目名>-放映页.html` / `<项目名>-演示稿.pptx` | 成品 |

文件名必须能一眼看出是什么：**写「大纲」，不写 `outline`；写「逐页内容」，不写 `slidespec`**。

## Step 0 · 每次开工前必做

1. 读 `references/judgment-library.md`（偏好库，公共层）。
2. 检查 `~/.workbuddy/ppt-private/judgments.local.md`——存在就一并读，冲突以私有层为准。
3. 读**表达方法**索引：`references/style-library/README.md`（14 种，管怎么论证）。
   视觉皮索引（`references/visual-library/README.md`，5 种，管长什么样）**留到 Step 4 再读再问**——皮是「长什么样」，等到真要画的时候选才不浪费（J-26）。
4. 判断这次是**新建**还是**改已有稿**：
   - 新建 → 从 Step 1 走。
   - 改已有稿 → 先读它现有的 `<项目名>-大纲.html` / `<项目名>-逐页内容.html`，判断改动落在哪一层，**回到那一层重做**，不要直接改成品页。

## 选型提案协议

**两层共用一套内容写法，但载体不同：表达方法弹卡片（筛 2–3 个让用户点）；视觉皮直接打开包内 `视觉皮选型页.html` 交给用户，页面给完再弹岔路卡，不列文字清单。**（J-48、J-49、J-52、**J-56**）

### 单条内容怎么写（两层共用，缺括号 = 不合格）

```
经营回顾（适合：季度 / 年度经营会、向上汇报结果）— 结果 / 差异 / 原因 / 责任承诺四段拆开
```

- 「适合」写**什么时候该用它**，日常说法，不写术语、不写英文 id。
- 破折号后写**它怎么讲 / 它长什么样**，一句说完。
- 整条 ≤ 45 字。**只报名字 = 不合格。**

### 表达方法：筛 2–3 个，弹卡片让他点

**不要列 14 个。** 14 行没人读，用户要的是一个能点的判断。

1. **前提**：Step 1 的「听众 / 场合 / 目标」三个原词已经在手。没问到就先问这三件，**没有场合的推荐是瞎猜**。
2. **筛三个**：
   - 第 1 个 · 场合正对：经营会→经营回顾；事故→故障复盘；投标售前→方案提案；融资→投资人路演；答辩→学术研究；培训→工作坊教学；发布→产品发布；高层拍板→MBB 战略咨询或决策咨询；对外行→科普讲解；大会演讲→叙事主题演讲；同行评审→技术深潜；比稿→创意提案；制度→制度手册
   - 第 2 个 · 目标正对：要一个决定→决策咨询；要资源预算→经营回顾；要认同→叙事主题演讲；要照着做→工作坊教学或制度手册
   - 第 3 个 · **气质相反**：让他看见另一条路
   - 只有一个明显合适就给 2 个。**凑数 = 不合格。**
3. **发卡片**：`AskUserQuestion`，一题单选。
   - `header` 固定 `讲法`；问句写 `这场用哪种讲法？我按「<场合> / <听众> / <目标>」筛了 N 个。`
   - `label` = 中文名（≤6 字）；`description` = `适合：<场合> —— <内核>`
   - 每题最多 4 格，**我们只用 2–3 格，第 4 格宁可空着**——塞满等于又给了个候选池。
4. **卡片外补一句**：`库里共 14 种；想用别的直接说名字，我换。`
   **这句不能省**——不写，用户会以为库里只有 3 种，那不是筛，是瞒。
5. 用户点完即定，写进 `需求简报.md` 的选型记录，**不再追问为什么没选别的**。

**没有卡片能力的场合**（工具不可用 / 纯文本终端）：退回三条文本，一条一行、句式不变。**绝不退回摊 14 条。**

### 视觉皮：先给页面，再弹「走哪条路」（J-56）

Step 4 才问（J-26）。**三步，顺序不可倒：**

**第 1 步 · 打开选型页交给用户**（不是列文字）。打开包内 `视觉皮选型页.html`——**原地 `file://` 打开，不复制到项目目录**（J-49）；宿主有预览能力就直接把页面交给用户。正文只写两样：

1. **一句怎么用**：页面上 5 张卡，点缩略图在新标签打开整份示例稿，凑近看再回来挑。
2. **一句推荐 + 理由**：按「场合 + 听众 + 表达方法」挑第 1 条，说清为什么是它。

要标推荐位就带查询串：

```
视觉皮选型页.html?rec=paper-cut
```

`rec` 只认 `pop-collage | soft-sticker | paper-cut | sketch-notes | award-gold | none`。

> **⛔ 只列 5 行文字 = 不合格。** 用户明确否过这个做法：「你只给这个 HTML，给这个链接，不要只给文字」（J-56）。文字清单只在**页面打不开**（无预览能力 / 纯文本终端）时兜底，那时才退回 5 条 `名称（适合：场合）— 内核`，末尾挂 `已给 5/5 · 全库就这 5 种`。

**第 2 步 · 弹卡片 A「走哪条路」**——页面给完之后才发，不能提前：

| 题 | `header` | 格 | 为什么问 |
|---|---|---|---|
| 走哪条路 | `视觉皮` | 从模板里选 · 我自己给参考 | 内置 5 种不是唯一来源，只是最近的一条 |
| 要不要 AI 配图 | `配图` | 不要图 · 少量配图 · 逐页配图 | 主视觉定不下来，样张没法做（J-53） |

- 格 1「从模板里选」→ 等他报名字，进第 3 步的分叉 A。
- 格 2「我自己给参考」→ 发卡片 B。
- **只看页面就想定了、直接报了皮名** → 卡片 A 跳过不发，配图题单独补问一句。已交代的不重问（J-50 第 3 条）。

**第 3 步 · 分叉**：

- **岔 A 用模板**：报中文名直接定，读该皮规格，进 4.2 样张。
- **岔 B 不用模板**：**发卡片 B**（一题，`header` 固定 `参考图`，问句「参考图谁来出？」）：

  | 格 | `description` 写什么 |
  |---|---|
  | 我自己出图发你 | 你手上已有截图 / 网站 / 现有 HTML，发我就照着做 |
  | 你按内容生成几版我挑 | 我先分析这份稿子，出 3–4 版同页试片给你挑 |
  | 我不确定，你先出 | 同上，你不必先想清楚要什么 |

  **第 3 格就是「我不知道参考什么」的入口**——用户点它，你不必去猜他那句话是什么语气（J-52）。
  - 选第 1 格：**停下等图**。图没到不发样张；卡片传不了文件，让他直接在聊天框发。
  - 选第 2 / 3 格：走 4.1c 试片。

**四条禁令**（改后仍然有效）：
1. **选型页是第 1 步，不是可选项**——不许先列 5 行文字再问「要不要看图」。顺序反了就是 J-56 记的那次返工。
2. **页面给了也得等一句话。** 页面上点了卡 ≠ 已确认（页面没有回传通道），他报了名字或说「就这样」，才能进 4.2。
3. **卡片 A 不许抢在页面之前发**。没看见有什么，就没法判断要不要自己给参考。
4. **皮与岔路走卡片，出图走卡片 B，是两件不同的事**，别混成一张卡。

### 用户怎么答，你怎么接

| 用户说 | 做法 |
|---|---|
| 点了某个 / 说第 2 个 | 直接定，不再追问理由 |
| 说了个不在卡片上的名字 | 对回中文名直接定；报英文 id 也要能对上（J-32） |
| 你定 / 随便 | 取卡片第 1 个，一句话说为什么 |
| 跟上次一样 | 取上次记录的那个，不重问 |
| 卡片上这几个都不合适（表达方法） | 报剩下那些的名字让他挑（库里共 14 种）；都不对就请他给一句感觉或一份参考，**不现编** |
| 页面上 5 种都不合适（视觉皮） | **库里只有这 5 种、已全给过**，不再报「剩下的」；转卡片 B 走岔 B，请对方给参考或让你出试片 |
| 想看看长什么样 / 有样张吗 | **不用等他说**——问皮的第一步就该是打开选型页（J-56）；他这句说明你上一步漏了，立刻补 |
| 我不知道参考什么 / 你出几版我看看 | **卡片 B 第 3 格**，出 3–4 版同页试片（4.1c） |
| 要库里没有的 | 明说没有，转卡片 B：给参考，或让你出试片，**不现编成第 7 种皮** |

## Step 1 · 收料

目标：把「我想做个 PPT」变成一份能开工的 brief。

必问八项，**全部走 `AskUserQuestion` 弹卡片**，但一张卡装不下——一次最多 4 题，所以**拆两张**（J-50）。

### 第 1 张卡（4 题，先发，不依赖任何前置信息）

| 题 | `header` | 选项（`label`） | 为什么必须问 |
|---|---|---|---|
| 听众 | `听众` | 领导 / 上级 · 客户 / 甲方 · 团队内部 · 学员 / 新人 | 决定详略和语气 |
| 时长 | `时长` | 10 分钟以内 · 15–20 分钟 · 25–30 分钟 · 40 分钟以上 | 决定页数（≈ 1.5 分钟/页） |
| 目标 | `目标` | 要一个决定 · 要资源 / 预算 · 要认同支持 · 要他们照着做 | 目标定主线——不是「讲完」 |
| 场合 | `场合` | 部门例会 · 向上汇报 · 客户提案 / 投标 · 培训 / 评审 | 定装饰密度与正式度（J-26） |

### 第 2 张卡（4 题，第 1 张答完再发）

| 题 | `header` | 选项（`label`） | 为什么必须问 |
|---|---|---|---|
| 表达方法 | `讲法` | **按「选型提案协议」筛 2–3 个**，第 4 格空着 | 决定页序怎么排。**依赖第 1 张的场合 / 听众 / 目标** |
| 交付形态 | `交付形态` | HTML 放映页（默认）· 可编辑 PPTX · 逐页生图 PPTX | 决定 Step 4 走哪条路。用户说「PPT」就绝不给 HTML |
| 目录页 | `目录页` | 要 · 不要 | 不按页数替用户猜（J-31 / J-40） |
| 资料 | `资料` | 我传文件 · 我贴文字 · 已有稿子（给路径）· 没有资料，你上网搜 | 决定 Step 2 的素材边界。**没料不许写大纲**（J-51） |

**两张卡通用写法：**

- 每题 **2–4 格**，`label` ≤6 字、点得动；`description` 写「选了会怎样」一句话，不写术语、不报英文 id。
- **不许自建「其他」选项**——UI 底部自带自由输入，再加就重复了。所以枚举不完的项（听众、场合）**只放最可能的 4 个**，剩下的靠用户在 Other 里说。**筛得准比放得多重要。**
- 用户首条消息里已经交代过的项**直接不弹**：说「给领导看，10 分钟的例会」→ 听众 / 时长 / 场合三格跳过，只弹缺的。别把已知的再问一遍。**资料题跳过时（他首条消息就带了附件 / 链接 / 正文），当场把这份材料记进 brief 的资料清单**——来源、路径、覆盖内容，一样不能少，否则 2.0 门禁会误拦。
- 一张卡里用户没答的题（关了卡片 / 只点了两题），**下一轮补弹**，不要自己填。整轮最多两轮（含补问）。
- 用户答「你定 / 都行」：听众取「领导 / 上级」、时长取 15–20、目标取「要认同支持」、场合取「向上汇报」、形态取 HTML、目录取「要」，**一句话说为什么**，直接往下走。
- 两张卡都发完，**把 8 项复述成一行**让用户扫一眼（「领导 · 15 分钟 · 要认同 · 部门例会 · 经营回顾 · HTML · 要目录 · 资料你传」），有错当场改。

> **「资料」是半张卡**：卡片问的是**以什么形式给我**，不是「资料在哪」。选了「我传文件」就等文件到；选了「已有稿子」再要路径。**文件永远在聊天框里传，卡片传不了。**
>
> **第 4 格「没有资料，你上网搜」是唯一能空手开写的入口**——它本身就是搜索授权，选了就等于说「不用我给资料，你去找」。**没有这个授权、手上又没料，Step 2 一律不许动笔**（J-51，见 2.0）。「你来写」这种格子不许再出现。
>
> **视觉皮不在这里问。** 它决定的是「长什么样」，而 Step 2、Step 3 都不写颜色不写字体（J-01），早问没有落点。放到 Step 4 制作前再问（4.1）。
>
> **表达方法对用户报中文名**（MBB 战略咨询 / 经营回顾 / 工作坊教学 …），不报英文 id。id 只作 `specs/<id>/` 目录名，内部用。
>
> **第 2 张卡是依赖卡**：讲法要按场合筛，**没有场合就筛，那是瞎猜**。所以第 1 张没答完、第 2 张不发。

产出 `需求简报.md`，模板见 `templates/brief.md`。

**硬规则**：资料里出现的数字，只要来源不明，就在 brief 里标 `[待确认]`，不许带进大纲。

## Step 2 · 出大纲

### 2.0 先过资料门禁（不过不许动笔）

**这是硬门槛，不是提醒。** 写大纲前逐条查：

| # | 条件 | 判定 |
|---|---|---|
| 1 | `需求简报.md` 的资料清单里**至少 1 条有实际内容**：文件已收到 / 路径能打开 / 链接可访问 / 正文已贴在对话里 | 满足即放行 |
| 2 | brief 里记着 `搜索授权：已给`（用户在卡片点了「没有资料，你上网搜」，或明说「你上网搜 / 不用我给资料 / 你去找」） | 满足即放行，转 2.0.1 |
| 3 | 两条都不成立 | **⛔ 停。一个字都不许写。** |

**拦住时照抄这段话术**，不要临场发挥：

> 大纲我先不动：手上没有你的材料，硬写就是编。两条路选一条——把资料发我（文件 / 链接 / 直接贴文字都行），或者回一句「你上网搜」，我去找公开数据，搜到的数字会标来源、等你核实。

**「卡片上选了传文件、但一直没传」也算没资料**，同样拦。不许拿「他大概是想让我先搭个架子」当理由往下写——空着料写出来的大纲，全是编的。

### 2.0.1 授权搜索时的四条边界

1. **搜前报方向**：先报 3–5 个搜索方向，用户点头再搜，不闷头搜一堆无关的。
2. **搜后报账**：找到几条、用哪几条、弃了哪几条，各一句。
3. **数字一律标 `[网搜·待核实]`**，沿用 J-03：未经用户确认不进正文数据格，只在附录「数据来源」里列。
4. **用户后补资料时以他的为准**：与搜来的冲突就弃搜来的，并在 brief 里记「X 项原用网搜，已换用户口径」。

默认只做**轻度搜索**（补公开数据与背景），要深挖让用户自己说。

### 2.1 先过偏好库（关键步骤）

不要直接写大纲。先按偏好库生成一张**默认处理清单**，交给用户确认。

规则：
- 只列**这次资料真会碰到**的条目，最多 6 条。
- 每条写：编号 · 一句话结论 · 本次默认怎么做 · 要不要改。
- 用户回「都行 / 按默认」就直接走；改哪条就记哪条。
- **这张清单不走 `AskUserQuestion`，就用表格文字摆。**（J-50）`description` 只有一两行的容量，装不下「编号 · 结论 · 本次默认」三段，硬塞必然丢信息；而且清单默认是「全部遵守」，卡片做成选项反而逼用户在没意见的地方做选择。**直接文字问一句「有要改的直接说」。**

格式示例：

```
这次会碰到 4 条判断，默认这么处理：

| 编号 | 判断 | 本次默认 |
|---|---|---|
| J-01 | 大纲不写配色 | 遵守 |
| J-05 | 抓大放小：过程细节默认不写 | 课程设计、运营机制不进大纲 |
| J-08 | 清单要全，讲解要挑 | 只挑 3 个代表作 |
| J-02 | 结构由用户定 | 按用户给的分法 |

有要改的直接说。
```

### 2.2 定主线

先写一句话主线（整份 PPT 只允许有一条）：

> 「用 30 天把『学过』变成『做出来』」

主线必须满足：**能被反驳**。不能被反驳的是口号，不是主线。

主线定完，全部素材只分两类：**撑得住的（放大）** 与 **撑不住的（丢掉或压成一句）**。不要因为「我们确实做过」就写进去——这一步就是抓大放小。同一块素材在讲「做成了什么」时是废话，在讲「为什么能成」时是正题，先判场合再判去留。

### 2.3 搭骨架

- 一级结构不超过 **3 块**（超过就说明还没想清）。
- 每块下面 2–4 个小节。
- 每个小节写：**一句结论**（不是标题）+ **支撑它的 2–3 个事实/数据**。
- **主线与页序按选定的表达方法排**：表达方法（MBB 战略咨询、经营回顾、产品发布…）决定论证怎么排，同样的素材换个方法，顺序完全不同。别自己发明顺序。视觉皮这里还不参与。

产出 `<项目名>-大纲.html`，骨架见 `templates/大纲模板.html`。**交出去的就是这个 HTML，不另存 md**——浏览器直接打开，你看到的就是终稿形态。

**模板里有三种载体，相邻两部分必须换型**（都同型 = 视线一路向下滚）：
- **层级堆叠**（竖条，编号在左标签内）— 适合几块平行、无先后
- **诊断卡**（两列，结论当卡标题）— 适合逐项下判断、每项自带立场
- **时间轴**（竖线，`.key` 标红点）— 适合有先后或有转折

三条硬规定，违反即返工：① 全篇一条对齐轴，不许各自缩进；② 结论 19px 粗 / 证据 13px 小字，差分必须跨档；③ 主线只出现一次，页数进顶部数字带，不再单开「页数估算」表。

**小节不编号**（J-38，2026-10-25 用户定案）：页面上只留部分号 01/02/03，`1(a)` `2(b)` `3.1` 这类复合编号一律不许出现。改稿时用「部分号 + 结论里能认出它的几个字」指认，例如「02 里讲积分那条，结论反了」。附录类内容（口径订正、数据来源、未采用的说法）用 `idx=附`，不占一级部分。

**目录在左侧，不在顶部**（J-39）：`nav.side` 固定侧栏，`position:sticky`，点哪跳哪。**不要做成顶部横向胶囊导航**——会顶掉第一屏、且随滚动消失。窄屏（≤1080px）自动折成横排胶囊，打印时整条隐藏。

**⛔ 门禁**：写完就停，把这份 HTML 交给用户打开看，等「通过」。
用户没说通过，绝不进入 Step 3。

## Step 3 · 出逐页内容

### 3.1 再过一次偏好库

粒度变了，判断也要重问。这次重点问：
- 哪些内容**留在这一页**、哪些该单独一页、哪些直接砍掉
- 长清单要不要拆页
- 哪些页需要讲稿、哪些不需要

同样只问碰得到的条目。**和 2.1 一样走文字清单，不上卡片**（J-50）：这三问是逐条内容的取舍，条数随稿子变，选项框不住；而且「留这一页 / 单独一页 / 砍掉」是同一份清单上的三种标法，做成卡片就得每页一张卡，反而更烦。

### 3.2 拆页

一页一个观点。每页必须有：

| 项 | 要求 |
|---|---|
| `data-page` | 页码，从 00 开始 |
| `data-role` | `封面 / 目录 / 章节 / 内容 / 结尾` |
| `data-note` | 讲稿。口头补什么，一句话，不写逐字稿 |
| Action Title (`h2.at`) | **一句结论**，不是名词短语。看到标题就知道这页在说什么 |
| 页面内容 | **直接排成页**——上屏的字就是最终的字，能用表格/清单就不用段落 |

**不再写「页面内容 / 版式 / 讲稿」三行字段表。** 版式由你把页面画出来这件事本身表达，不需要再用文字描述一遍。

页数控制：
- 15 分钟 ≈ 12–16 页
- 25 分钟 ≈ 18–24 页
- 更长就自行折算

**目录页不设页数门槛，在 Step 1 直接问用户「要不要加目录页」。** 用户说要就加，说不要就不加——不要用「超过多少页才需要」替用户决定。

节庆页（封面 / 目录 / 章节 / 结尾）单独计数，不算在内容页里。

产出 `<项目名>-逐页内容.html`，骨架见 `templates/逐页内容模板.html`——**它本身就是主页内容的可跑页面**，不是字段表。

**固定的只有外壳**：每页 `section.slide` 都是白底、圆角、细边框的卡片，竖向堆叠、等比缩放。**卡片内部完全自由**：编号写不写、小字放不放、页码要不要、几栏几格、字号疏密，全按这一页的内容自己判断，不要求前后统一（J-30）。

**结构不能改**：`<section class="slide" data-page data-role data-note>` + `<h2 class="at">`。Step 4 靠这三个属性取页序与讲稿，改了下游就断。

**⛔ 门禁**：写完就停，交 HTML 给用户打开看，等「通过」。

### 4.1 先问视觉皮（制作前唯一要问的问题）

为什么不放在 Step 1 问：Step 2、Step 3 都不写颜色、不写字体（J-01），皮在审稿阶段没有落点。挪到这儿，用户是在「已经认可结构、马上要变成页面」的语境下选皮，选得准。

- 用户说「你定」→ 按场合挑最贴的，默认回落波普拼贴
- 用户说「跟上次一样 / 还是那个风格」→ 直接取上次定的皮，别重问

选定后读它的规范 +（若自带）参考实现：

### 4.1b 配图层级（不单开一轮，跟着卡片 A 一起问）

**为什么必须落在样张之前：** 有主视觉和没主视觉是两种调性——封面是「满版一张图」还是「纯字排版」，字号、留白、层级全都不一样。**样张做完再问，等于封面重做**（J-53）。

三档，跟着卡片 A 的第二题点：

| 选了什么 | 意味着什么 |
|---|---|
| 不要图 | 纯排版，靠形状 / 色块 / 字号立层级。封面不预留图位 |
| 少量配图 | 只封面 + 章节页要主视觉，内容页不插画 |
| 逐页配图 | 每页都有视觉，等同逐页生图那条线，生图量大 |

**两条互斥判定：**

- Step 1 形态已选 `逐页生图 PPTX` → 这题**锁死为「逐页配图」，不问**。同一件事问两遍是浪费。
- 用户说「就这样，不换皮」→ 图仍可要，但只在白底卡片内部排版，不做满版出血。

选了「少量 / 逐页」且**走 HTML 放映页或可编辑 PPTX** 时，图片来源按顺序取：项目目录 `images/` 里已有的 → 借该皮 `assets/` 里的参考资产（同皮才许借，_style-contract §三 第 5 条）→ 都不够才走宿主 ImageGen 生图。**生图一律文字不进图**（J-18）。

### 4.1c 用户自己不给参考时，出试片让他挑

**触发条件只有一个：卡片 B 选了第 2 格或第 3 格。** 用户没点这个，你就不要主动出片。

1. **先分析内容定方向**，别一次性瞎出。从稿子里取三样：听众与场合（决定稳还是冲）、主线（决定视觉主角是什么）、有没有硬数字（决定要不要数据化图形）。据此写 **3–4 个方向**，每个方向一句话：`稳 / 冲 / 仪式 / 亲和` 挑一个 + 一句视觉语法。
2. **同一页换皮**：取稿子的**封面 + 第一张内容页**，**标题、数字、正文字一个字都不许动**，只换形状语言、装饰密度、字号阶、质感。三版都用真内容，否则比的是内容不是风格。
3. **3–4 版封顶**。一屏能并排比完；多了用户挑不动，而且每版都得真做，成本在他自己身上。
4. **出图走宿主 ImageGen**（J-18 口径，不用外部链路）。**文字永远不进图**——试片里的标题也要是原生文本，否则用户挑完你没法改字。
5. **挑完写一份临时皮规格**：落 `ppt/<项目名>/临时视觉皮.md`，写清调性、色板（底 / 主 / 强调三个 HEX，此处**必须确认色值**）、字号阶、视觉语法、安全区。**不进包、不写进 `visual-library/`**——库里仍是这 5 种，别让一次性的皮污染库。
6. 拿到临时皮规格后进 4.2 样张，三页照样要过门禁。

> **不进包是硬规定。** 自定义皮只活在这个项目里，下次换项目重新选。用户如果反复用到同一套，再问他「要不要正式收进视觉库」，那才走 `visual-library/README.md` §四 的六步。

### 4.2 先做三页样张，等确认（门禁）

**皮定了不等于方向对了。** 批量做十五页再返工是最贵的浪费，所以先做三页给用户看（J-28）。

**这三页就是主页内容 HTML 的前 3 页**——`00`、`01`、`02`，原样拿，不另挑页型：

- `00` 封面 → 验调性：主视觉、字号层级、留白尺度
- `01` 第二页 → 验层级：标题、序号、分隔撑不撑得住结构
- `02` 第三页 → 验密度：装不装得下真实内容，会不会崩

有三页就够，不必凑成「封面 / 目录 / 内容」——稿子里本来就没有目录页时，硬凑一页是浪费。

**样张怎么给：**

| 形态 | 做法 | 文件名 |
|---|---|---|
| HTML 放映页 | 就用前 3 个 `<section class="slide">`，能翻页就行 | `<项目名>-样张三页.html` |
| 可编辑 PPTX | 只放前 3 个 svg 进 `svg_output/`，跑一次 `build_pptx.py` | `<项目名>-样张三页.pptx` |
| 逐页生图 PPTX | 三页各生一张底图，文字仍原生 | 同上 |

**⛔ 门禁：** 用户明确说「满意 / 可以 / 继续」，才铺开做剩下的。说「再调调」就**只改这三页重出**，不碰后面的页。

问法照这个说：

> 前 3 页样张给你了。看两件事：调性对不对，密度撑不撑得住。满意我就铺开做剩下 N 页。

### 4.5 可编辑 PPTX（一条命令出片）

**不转交内容，也不碰上游命令。** 你自己按 `逐页内容.html` 写 SVG 页，出片交给专家自己的入口脚本。

写页前必读一份：`deckcore/references/shared-standards-core.md`（SVG 书写契约，259 行）。不读它，质量检查会拒。

> 入口脚本吃英文 slug（它要拼目录名、写回路径）。**交给用户的成品文件名仍用中文**：脚本出片后改名/另存为 `<项目名>-演示稿.pptx`，并把中文名报给用户。

**两步：**

```bash
# 第一次：搭脚手架（会建项目、告诉你页往哪放）
python scripts/build_pptx.py <workspace> <slug>

# 写完页再跑同一条：校验 → 导出 → 回写路径
python scripts/build_pptx.py <workspace> <slug>
```

要带讲稿备注加 `--notes`；想先看步骤加 `--dry-run`；指定输出加 `--out`。

**页的写法**（`<project>/svg_output/` 里，一页一个 `.svg`）：

- 根 `<svg>` 必须带 `width="1280" height="720"`、`viewBox="0 0 1280 720"`、`lang="zh-CN"`
- 文字用原生 `<text>`（**导出后是 `TEXT_BOX`，可编辑**）
- 图标用**内联 `<path>`**（导出后是原生形状），别找图标库——包里没有（J-25）
- 配图放 `<project>/images/`，`<image>` 引相对路径；**别把字烤进图**（J-18）

**四条硬项（2026-10-24 实测定案：缺任何一条都会吃告警，全齐才能 `status=passed`、0 告警）：**

1. **根 `<svg>` 只给排版默认值，绝不给 `fill`**——有可见文字时直接在根上给 `font-family` / `font-size` / `font-weight`；共享涂色下沉到各 `<g>`。
2. **每个可见根 `<g>` 必须带 `data-pptx-bounds="x y width height"`**——缺了直接 blocking 失败，不是告警。
3. **带 `data-pptx-role` 的元素必须有稳定 `id`**——背景/装饰等静态画框同样要。
4. **色值用大写 `#RRGGBB`**——小写十六进制是兼容的，但每处都会吃一条建议告警。

整页声明 `data-pptx-page-role="content"`（扁平页），每个逻辑单元包一个带 id 的根 `<g>`。

> **别照着报错建议逐条补**——建议文案不完整（提示补 `id` + `role` 却不提 `bounds`，照做会从告警变失败）。直接从骨架抄：`deckcore/references/page-skeleton.svg`，复制后改内容。也不要指望 `compact_svg_styles.py` 兜底：实测它只能把告警从 6 降到 4，补不了 `bounds` 和 `page-role`。

**这个入口脚本替你处理了什么**（所以别再自己敲引擎命令）：

- `--dir` 已指到 `<workspace>/ppt`，**不会**建到插件目录里（C-01）
- 目录带 `_YYYYMMDD` 后缀，脚本会把真实路径写回 `ppt/<中文项目名>/需求简报.md`（C-02）
- 用当前解释器跑引擎，**绕开 Windows 上 `python3` 是假壳的坑**（C-08）
- 先跑引擎完整性校验，非 0 立刻停，不修不绕（C-07）
- 质量检查必须 exit 0 才继续，导出后回读页数

### 4.6 逐页生图 PPTX

**和 4.4 完全同一条流水线，只在写页前多一段生图。**

1. **拆视觉需求**：逐页标出哪些元素要生图——封面主视觉、章节页背景、插图、装饰；哪些页纯文字不要图。
2. **写 prompt**：从选定视觉皮的规格里抽**视觉语法 + 色板 + 质感 + 构图密度**（J-18）。**不要让每页各自发挥**。
3. **出图**：宿主 ImageGen 逐张生成，存 `<project>/images/`。多个小元素用一张 sheet + 切图（`deckcore/scripts/slice_images.py --trim --alpha --bg`），别为一个小图标单生一张。
4. **写页**：把图用 `<image>` 嵌进页，**文字仍用原生 `<text>`**。
5. **出片**：同 4.4，跑 `build_pptx.py`。

**硬规矩**：标题、结论、数字**永远不许烤进图片**——生图只出视觉，不出字。

### 4.7 自检（交付前必跑，按形态分开做）

**HTML 放映页：**

1. 逐页截图：无头 Edge，`--window-size=1280,720`，一次 4–6 张，别批量超时。
2. 每张看三件事——文字有没有溢出、块有没有错位、层级清不清楚。
3. 首屏、末屏、每个章节页必须点名看过。
4. 外链检查：不许出现第三方图床域名。

**PPTX（没有 HTML 可截，别照 HTML 那套做）：**

1. 看 `build_pptx.py` 打印的 `quality_gate`，必须是 `passed`。
2. 用 python-pptx 打开，核对页数与 `逐页内容.html` 一致。
3. 逐页确认关键内容是 `TEXT_BOX` 原生文本框，不是整页一张图。
4. 有配图的页，核对图片没压住文字。

**两种形态都适用：** 内容与 `逐页内容.html` 对不上（少页、改词、改数）就是不合格，改了重跑。

不合格就改，改完重跑。**没看过产物不算做完。**
