# 汇报演示工作流

四个门，三道审核。**跳过任何一个门，这次产出就是废的。**

```
┌─ Step 1 收料 ────────► 需求简报.md          （不用审，问清即可）
├─ Step 2 出大纲 ──────► <项目名>-大纲.html      ⛔ 必须等「通过」
├─ Step 3 出逐页 ──────► <项目名>-逐页内容.html  ⛔ 必须等「通过」
└─ Step 4 出页面 ──────► 问视觉皮 → 三页样张 ⛔ 等「满意」→ 铺开 → 放映页.html / 演示稿.pptx
```

工作目录：`<workspace>/ppt/<中文项目名>/`。**所有产出文件一律中文命名**，同放一处，永不分散（见 J-27）。

| 阶段 | 文件名 | 说明 |
|---|---|---|
| Step 1 | `需求简报.md` | 收料结果 |
| Step 2 | `<项目名>-大纲.html` | 审阅载体，浏览器直接打开 |
| Step 3 | `<项目名>-逐页内容.html` | 审阅载体，同上 |
| Step 4 样张 | `<项目名>-样张三页.html` / `.pptx` | 只做前三页，等确认满意 |
| Step 4 成品 | `<项目名>-放映页.html` / `<项目名>-演示稿.pptx` | 成品 |

文件名必须能一眼看出是什么：**写「大纲」，不写 `outline`；写「逐页内容」，不写 `slidespec`**。

## Step 0 · 每次开工前必做

1. 读 `references/judgment-library.md`（偏好库，公共层）。
2. 检查 `~/.workbuddy/ppt-private/judgments.local.md`——存在就一并读，冲突以私有层为准。
3. 读**表达方法**索引：`references/style-library/README.md`（14 种，管怎么论证）。
   视觉皮索引（`references/visual-library/README.md`，22 种，管长什么样）**留到 Step 4 再读再问**——皮是「长什么样」，等到真要画的时候选才不浪费（J-26）。
4. 判断这次是**新建**还是**改已有稿**：
   - 新建 → 从 Step 1 走。
   - 改已有稿 → 先读它现有的 `<项目名>-大纲.html` / `<项目名>-逐页内容.html`，判断改动落在哪一层，**回到那一层重做**，不要直接改成品页。

## Step 1 · 收料

目标：把「我想做个 PPT」变成一份能开工的 brief。

必问（缺一不可，一次问完，不要分三轮）：

| 项 | 问法 | 为什么必须问 |
|---|---|---|
| 听众 | 给谁看？领导 / 客户 / 团队 / 学员 | 决定详略和语气 |
| 时长 | 讲多久？ | 决定页数（≈ 1.5 分钟/页） |
| **目标 + 场合** | **同一问里一起问**：听完你希望他们做什么 / 记住什么？这场是什么场合（例会 / 部门汇报 / 对外宣讲 / 培训）？ | 目标定主线——不是「讲完」；场合定装饰密度与正式度（J-26） |
| 表达方法 | 讲法上要怎么走？`style-library/README.md` 里 14 种骨架，各自适合什么场合，一起摆出来 | 决定页序怎么排。**这里只问表达方法，不问视觉皮** |
| 交付形态 | HTML 放映页（默认）/ 可编辑 PPTX / 逐页生图 PPTX | 决定 Step 4 走哪条路 |
| 目录页 | **要不要加目录页？** | 不要按页数替用户猜。说加就加，说不要就不加 |
| 资料 | 资料在哪？有没有口径要求 | 决定 Step 2 的素材边界 |

> **视觉皮不在这里问。** 它决定的是「长什么样」，而 Step 2、Step 3 都不写颜色不写字体（J-01），早问没有落点。放到 Step 4 制作前再问（4.1）。
>
> **表达方法对用户报中文名**（MBB 战略咨询 / 经营回顾 / 工作坊教学 …），不报英文 id。id 只作 `specs/<id>/` 目录名，内部用。

产出 `需求简报.md`，模板见 `templates/brief.md`。

**硬规则**：资料里出现的数字，只要来源不明，就在 brief 里标 `[待确认]`，不许带进大纲。

## Step 2 · 出大纲

### 2.1 先过偏好库（关键步骤）

不要直接写大纲。先按偏好库生成一张**默认处理清单**，交给用户确认。

规则：
- 只列**这次资料真会碰到**的条目，最多 6 条。
- 每条写：编号 · 一句话结论 · 本次默认怎么做 · 要不要改。
- 用户回「都行 / 按默认」就直接走；改哪条就记哪条。

格式示例：

```
这次会碰到 4 条判断，默认这么处理：

| 编号 | 判断 | 本次默认 |
|---|---|---|
| J-01 | 大纲不写配色 | 遵守 |
| J-05 | 抓大放小：过程细节默认不写 | 课程设计、运营机制不进大纲 |
| J-08 | 清单要全，讲解要挑 | 只挑 3 个代表作 |
| J-02 | 结构由用户定 | 按用户给的分法 |

有要改的直接说。
```

### 2.2 定主线

先写一句话主线（整份 PPT 只允许有一条）：

> 「用 30 天把『学过』变成『做出来』」

主线必须满足：**能被反驳**。不能被反驳的是口号，不是主线。

主线定完，全部素材只分两类：**撑得住的（放大）** 与 **撑不住的（丢掉或压成一句）**。不要因为「我们确实做过」就写进去——这一步就是抓大放小。同一块素材在讲「做成了什么」时是废话，在讲「为什么能成」时是正题，先判场合再判去留。

### 2.3 搭骨架

- 一级结构不超过 **3 块**（超过就说明还没想清）。
- 每块下面 2–4 个小节。
- 每个小节写：**一句结论**（不是标题）+ **支撑它的 2–3 个事实/数据**。
- **主线与页序按选定的表达方法排**：表达方法（MBB 战略咨询、经营回顾、产品发布…）决定论证怎么排，同样的素材换个方法，顺序完全不同。别自己发明顺序。视觉皮这里还不参与。

产出 `<项目名>-大纲.html`，骨架见 `templates/大纲模板.html`。**交出去的就是这个 HTML，不另存 md**——浏览器直接打开，你看到的就是终稿形态。

**⛔ 门禁**：写完就停，把这份 HTML 交给用户打开看，等「通过」。
用户没说通过，绝不进入 Step 3。

---

## Step 3 · 出逐页内容

### 3.1 再过一次偏好库

粒度变了，判断也要重问。这次重点问：
- 哪些内容**留在这一页**、哪些该单独一页、哪些直接砍掉
- 长清单要不要拆页
- 哪些页需要讲稿、哪些不需要

同样只问碰得到的条目。

### 3.2 拆页

一页一个观点。每页必须有：

| 项 | 要求 |
|---|---|
| `data-page` | 页码，从 00 开始 |
| `data-role` | `封面 / 目录 / 章节 / 内容 / 结尾` |
| `data-note` | 讲稿。口头补什么，一句话，不写逐字稿 |
| Action Title (`h2.at`) | **一句结论**，不是名词短语。看到标题就知道这页在说什么 |
| 页面内容 | **直接排成页**——上屏的字就是最终的字，能用表格/清单就不用段落 |

**不再写「页面内容 / 版式 / 讲稿」三行字段表。** 版式由你把页面画出来这件事本身表达，不需要再用文字描述一遍。

页数控制：
- 15 分钟 ≈ 12–16 页
- 25 分钟 ≈ 18–24 页
- 更长就自行折算

**目录页不设页数门槛，在 Step 1 直接问用户「要不要加目录页」。** 用户说要就加，说不要就不加——不要用「超过多少页才需要」替用户决定。

节庆页（封面 / 目录 / 章节 / 结尾）单独计数，不算在内容页里。

产出 `<项目名>-逐页内容.html`，骨架见 `templates/逐页内容模板.html`——**它本身就是主页内容的可跑页面**，不是字段表。

**固定的只有外壳**：每页 `section.slide` 都是白底、圆角、细边框的卡片，竖向堆叠、等比缩放。**卡片内部完全自由**：编号写不写、小字放不放、页码要不要、几栏几格、字号疏密，全按这一页的内容自己判断，不要求前后统一（J-30）。

**结构不能改**：`<section class="slide" data-page data-role data-note>` + `<h2 class="at">`。Step 4 靠这三个属性取页序与讲稿，改了下游就断。

**⛔ 门禁**：写完就停，交 HTML 给用户打开看，等「通过」。

## Step 4 · 出页面

### 4.1 先问视觉皮（制作前唯一要问的问题）

**这一步必须问用户，不许自己定。** 打开 `references/visual-library/README.md`，把 22 种按「适合什么场合」摆出来让他挑（J-26）——只报名字不合格，要带场合。

**一律用中文名**（瑞士极简 / 波普拼贴 / 深色科技 …），**不许对用户报英文 id**。英文 id 只是规格文件名，内部查表用。

为什么不放在 Step 1 问：Step 2、Step 3 都不写颜色、不写字体（J-01），皮在审稿阶段没有落点。挪到这儿，用户是在「已经认可结构、马上要变成页面」的语境下选皮，选得准。

- **用户说「就这样 / 不用换 / 保持现在这个」→ 直接沿用《逐页内容》的白底圆角卡片，不再套任何皮**，只做排版精修。这是最常见的一种答复，别追问
- 用户说「你定」→ 按场合挑最贴的，默认回落波普拼贴
- 用户说「跟上次一样 / 还是那个风格」→ 直接取上次定的皮，别重问
- 用户要的皮不在库里 → 明说「目前只有这 22 种，要么选一种，要么你先给我一个参考（截图 / 网站 / 现有 HTML）」，**不要现编一套皮**；用户说英文 id 也要能对上中文名

选定后读它的规范 +（若自带）参考实现：
- 波普拼贴：读 `pop-collage.md` + `pop-collage.reference.html`（18 屏可直接改内容复用）
- 鎏金颁奖 / 卡通形象：读同名 `.md` + `.reference.html`（5 屏 / 6 屏），素材在各自的 `assets/` 里
- 贴纸插画：读 `soft-sticker.md`（规范齐全，参考稿与道具图待建，按 10 类原型现场搭；角色图已退役，不从卡通皮借图）
- 其余 18 种 catalog：读 `../../../deckcore/references/visual-styles/<id>.md`，色值在制作阶段单独确认

> 自带四张皮都要按 `visual-library/_style-contract.md` 施工（E 层 7 变量、`<id>-` 前缀、资产不跨皮、字体不进包）。

> **白底圆角卡片不是视觉皮。** 那是《逐页内容》这个交付物本身的固定形态（Step 3 的规矩），不在 22 种里，也不参与风格选择。用户不换皮时，等于直接用这个形态做成品。

### 4.2 先做三页样张，等确认（门禁）

**皮定了不等于方向对了。** 批量做十五页再返工是最贵的浪费，所以先做三页给用户看（J-28）。

**这三页就是主页内容 HTML 的前 3 页**——`00`、`01`、`02`，原样拿，不另挑页型：

- `00` 封面 → 验调性：主视觉、字号层级、留白尺度
- `01` 第二页 → 验层级：标题、序号、分隔撑不撑得住结构
- `02` 第三页 → 验密度：装不装得下真实内容，会不会崩

有三页就够，不必凑成「封面 / 目录 / 内容」——稿子里本来就没有目录页时，硬凑一页是浪费。

**样张怎么给：**

| 形态 | 做法 | 文件名 |
|---|---|---|
| HTML 放映页 | 就用前 3 个 `<section class="slide">`，能翻页就行 | `<项目名>-样张三页.html` |
| 可编辑 PPTX | 只放前 3 个 svg 进 `svg_output/`，跑一次 `build_pptx.py` | `<项目名>-样张三页.pptx` |
| 逐页生图 PPTX | 三页各生一张底图，文字仍原生 | 同上 |

**⛔ 门禁：** 用户明确说「满意 / 可以 / 继续」，才铺开做剩下的。说「再调调」就**只改这三页重出**，不碰后面的页。

问法照这个说：

> 前 3 页样张给你了。看两件事：调性对不对，密度撑不撑得住。满意我就铺开做剩下 N 页。

### 4.3 形态分流

| 形态 | 走哪条 |
|---|---|
| HTML 放映页（默认） | 4.4 |
| 可编辑 PPTX | 4.5 |
| 逐页生图 PPTX | 4.6 |

**内容只有一份**，出处是 `逐页内容.html`。三条路只是渲染器不同，不许为不同形态重写内容。

### 4.4 HTML 放映页

按 `references/step4-build.md` 执行。核心约束：

- 固定舞台 `1280×720`，`fit()` 等比缩放，不响应式重排
- 每页一个 `<section class="slide">`，讲稿写 `data-note`
- 键盘 ← → / Space 翻页，`N` 开讲稿，`F` 全屏
- 只引用本地图或已授权直链
- 文件名：`<项目名>-放映页.html`

### 4.5 可编辑 PPTX（一条命令出片）

**不转交内容，也不碰上游命令。** 你自己按 `逐页内容.html` 写 SVG 页，出片交给专家自己的入口脚本。

写页前必读一份：`deckcore/references/shared-standards-core.md`（SVG 书写契约，259 行）。不读它，质量检查会拒。

> 入口脚本吃英文 slug（它要拼目录名、写回路径）。**交给用户的成品文件名仍用中文**：脚本出片后改名/另存为 `<项目名>-演示稿.pptx`，并把中文名报给用户。

**两步：**

```bash
# 第一次：搭脚手架（会建项目、告诉你页往哪放）
python scripts/build_pptx.py <workspace> <slug>

# 写完页再跑同一条：校验 → 导出 → 回写路径
python scripts/build_pptx.py <workspace> <slug>
```

要带讲稿备注加 `--notes`；想先看步骤加 `--dry-run`；指定输出加 `--out`。

**页的写法**（`<project>/svg_output/` 里，一页一个 `.svg`）：

- 根 `<svg>` 必须带 `width="1280" height="720"`、`viewBox="0 0 1280 720"`、`lang="zh-CN"`
- 文字用原生 `<text>`（**导出后是 `TEXT_BOX`，可编辑**）
- 图标用**内联 `<path>`**（导出后是原生形状），别找图标库——包里没有（J-25）
- 配图放 `<project>/images/`，`<image>` 引相对路径；**别把字烤进图**（J-18）

**四条硬项（2026-10-24 实测定案：缺任何一条都会吃告警，全齐才能 `status=passed`、0 告警）：**

1. **根 `<svg>` 只给排版默认值，绝不给 `fill`**——有可见文字时直接在根上给 `font-family` / `font-size` / `font-weight`；共享涂色下沉到各 `<g>`。
2. **每个可见根 `<g>` 必须带 `data-pptx-bounds="x y width height"`**——缺了直接 blocking 失败，不是告警。
3. **带 `data-pptx-role` 的元素必须有稳定 `id`**——背景/装饰等静态画框同样要。
4. **色值用大写 `#RRGGBB`**——小写十六进制是兼容的，但每处都会吃一条建议告警。

整页声明 `data-pptx-page-role="content"`（扁平页），每个逻辑单元包一个带 id 的根 `<g>`。

> **别照着报错建议逐条补**——建议文案不完整（提示补 `id` + `role` 却不提 `bounds`，照做会从告警变失败）。直接从骨架抄：`deckcore/references/page-skeleton.svg`，复制后改内容。也不要指望 `compact_svg_styles.py` 兜底：实测它只能把告警从 6 降到 4，补不了 `bounds` 和 `page-role`。

**这个入口脚本替你处理了什么**（所以别再自己敲引擎命令）：

- `--dir` 已指到 `<workspace>/ppt`，**不会**建到插件目录里（C-01）
- 目录带 `_YYYYMMDD` 后缀，脚本会把真实路径写回 `ppt/<中文项目名>/需求简报.md`（C-02）
- 用当前解释器跑引擎，**绕开 Windows 上 `python3` 是假壳的坑**（C-08）
- 先跑引擎完整性校验，非 0 立刻停，不修不绕（C-07）
- 质量检查必须 exit 0 才继续，导出后回读页数

### 4.6 逐页生图 PPTX

**和 4.4 完全同一条流水线，只在写页前多一段生图。**

1. **拆视觉需求**：逐页标出哪些元素要生图——封面主视觉、章节页背景、插图、装饰；哪些页纯文字不要图。
2. **写 prompt**：从选定视觉皮的规格里抽**视觉语法 + 色板 + 质感 + 构图密度**（J-18）。**不要让每页各自发挥**。
3. **出图**：宿主 ImageGen 逐张生成，存 `<project>/images/`。多个小元素用一张 sheet + 切图（`deckcore/scripts/slice_images.py --trim --alpha --bg`），别为一个小图标单生一张。
4. **写页**：把图用 `<image>` 嵌进页，**文字仍用原生 `<text>`**。
5. **出片**：同 4.4，跑 `build_pptx.py`。

**硬规矩**：标题、结论、数字**永远不许烤进图片**——生图只出视觉，不出字。

### 4.7 自检（交付前必跑，按形态分开做）

**HTML 放映页：**

1. 逐页截图：无头 Edge，`--window-size=1280,720`，一次 4–6 张，别批量超时。
2. 每张看三件事——文字有没有溢出、块有没有错位、层级清不清楚。
3. 首屏、末屏、每个章节页必须点名看过。
4. 外链检查：不许出现第三方图床域名。

**PPTX（没有 HTML 可截，别照 HTML 那套做）：**

1. 看 `build_pptx.py` 打印的 `quality_gate`，必须是 `passed`。
2. 用 python-pptx 打开，核对页数与 `逐页内容.html` 一致。
3. 逐页确认关键内容是 `TEXT_BOX` 原生文本框，不是整页一张图。
4. 有配图的页，核对图片没压住文字。
