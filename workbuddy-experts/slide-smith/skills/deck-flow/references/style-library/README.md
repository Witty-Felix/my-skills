# 表达方法库

**这一层只管「怎么论证」**：论证顺序、页序、证据要求、页面角色词汇、语气。
它**不管**长什么样——配色、字体、版式语法在 `../visual-library/`（视觉风格）。

两者正交，可任意组合。只借方法，不搬字段。

> **论证框架一律用中文名。** 跟用户沟通只报中文名（MBB 战略咨询 / 工作坊教学 …），不报英文 id。英文 id 只作内部标识与各方法 spec 的目录名，**不改名**。

---

## 一、14 种

| 论证框架 | 适合什么场合（对用户就这么说） | 一句话内核 | 内部 id |
|---|---|---|---|
| **MBB 战略咨询** | 给高层或董事会拍板、正式战略文件 | 结论先行 + 文档级信息密度，编号图表、页脚出处 | `mbb-consulting` |
| **决策咨询** | 在一堆选项里给出一个决定，并证明它 | 答案先行、证据驱动，视觉克制 | `consulting-decision` |
| **投资人路演** | 路演融资、见投资人 | 用证据而非形容词，带投资人走完「为什么是现在」到「为什么是这团队」 | `investor-pitch` |
| **经营回顾** | 季度 / 年度经营会，汇报结果与差距 | 结果 / 差异 / 原因 / 责任承诺四段拆开，不粉饰难看的数字 | `operating-review` |
| **故障复盘** | 出事故后对内复盘 | 无责化重建时间线，区分促成因素与责任，落到可验证的行动 | `incident-postmortem` |
| **产品发布** | 发布新产品或新能力，让听众想要 | 价值先行：每个能力主张先被一个可演示的时刻兑现，再命名 | `product-launch` |
| **方案提案** | 投标、售前，要赢下这个客户 | 先证明你懂我的处境，再用具体且有成本的方案赢下这份工作 | `solution-proposal` |
| **技术深潜** | 给技术同行讲架构、做方案评审 | 机制优先：每个主张落在约束、取舍和可观测行为上 | `technical-deepdive` |
| **学术研究** | 答辩、研究汇报，要经得起质疑 | 从问题、方法、结果构造可辩护的主张，并让局限始终可见 | `academic-research` |
| **科普讲解** | 给外行讲清一件专业的事 | 从熟悉的大地出发，用视觉类比建立理解，不为易懂牺牲准确 | `science-explainer` |
| **叙事主题演讲** | 大会演讲，要让听众认同一个观点 | 用张力、转折和具体的人物细节，把一个观点讲到能被接受 | `narrative-keynote` |
| **工作坊教学** | 培训上课，听众要跟着动手 | 目标 → 示范 → 练习 → 诚实的检验，序贯推进理解 | `workshop-teaching` |
| **创意提案** | 广告 / 品牌创意提案，卖一个点子 | 把一个真实洞察落地，并展示它如何活在每个出现的地方 | `creative-pitch` |
| **制度手册** | 制度 / 操作手册，让人照着执行 | 把散落的规则收拢到一条判断轴上，机制先于规则，每条可追溯到机制页 | `duty-manual` |

> **视觉皮不在这里。** 共 5 种视觉风格（本包自带 3 种 + catalog 2 种：波普拼贴 / 鎏金颁奖 / 贴纸插画），见 `../visual-library/README.md`。
> 注意：「白底圆角卡片页」不是风格，是 Step 3《逐页内容》这个交付物的固定形态，不在这 6 种里。

## 一之二、对用户怎么摆（筛 2–3 个，弹卡片）

**上面那张表是给你自己查的；念给用户的一律按这一节的走。**

### 先筛，再问

从 14 种里挑 **2–3 个**，用 `AskUserQuestion` 弹一题单选给他点。**不要列 14 行。**

- 第 1 个：场合正对；第 2 个：目标正对；第 3 个：**气质相反**，让他看见另一条路。
- 只有一个明显合适就给 2 个，**凑数 = 不合格**。
- 前提：「听众 / 场合 / 目标」三个原词已经在手。没问到就先问这三件——**没有场合的推荐是瞎猜**。

### 卡片怎么写

| 位 | 写什么 | 例 |
|---|---|---|
| `header` | 固定 `讲法` | 讲法 |
| 问句 | `这场用哪种讲法？我按「<场合> / <听众> / <目标>」筛了 N 个。` | 这场用哪种讲法？我按「季度经营会 / 事业部领导 / 要预算」筛了 3 个。 |
| `label` | 中文名，≤6 字 | 经营回顾 |
| `description` | `适合：<场合> —— <内核>` | 适合：季度 / 年度经营会 —— 结果、差距、原因、承诺四段拆开 |

选项最多 4 格，**我们只用 2–3 格，第 4 格宁可空着**——塞满等于又给了个候选池。

### 卡片外补一句

```
库里共 14 种；想用别的直接说名字，我换。
```

**这句不能省。** 不写，用户会以为库里只有 3 种——那不是筛，是瞒。

### 用户怎么答，你怎么接

| 用户说 | 做法 |
|---|---|
| 点了某个 / 说第 2 个 | 直接定，不再追问理由 |
| 说了一个没在卡片上的名字 | 对回中文名直接定；报英文 id 也要能对上 |
| 你定 / 随便 | 取卡片第 1 个，一句话说为什么 |
| 跟上次一样 | 取上次记录的那个，不重问 |
| 卡片上这几个都不合适 | 报剩下那些的名字让他挑；都不对就请他给一句感觉或一份参考，**不现编** |
| 要库里没有的 | 明说没有，请给参考（截图 / 网站 / 现有 HTML） |

**没有卡片能力的场合**（工具不可用 / 纯文本终端）：退回三条文本，一条一行、句式不变。**绝不退回摊 14 条。**

## 二、「表达」和「视觉」的区别

- **表达**（本目录 14 种）决定**怎么论证**：论证顺序、页序、证据要求、语气。
- **视觉**（`../visual-library/`）决定**长什么样**：配色、字体、版式语法、页面原型、质感。

**「MBB 战略咨询的论证骨架 + 波普拼贴的视觉皮肤」是成立的**——先按 MBB 排主线和页序，再用选定的皮落地。

如果用户分不清，就问一句：「更想要好看的皮，还是更想要会说服人的讲法」，或者按场合直接推荐。

## 三、选型速查

| 用户说 | 选 |
|---|---|
| 给领导看 / 要下结论 | MBB 战略咨询，或决策咨询 |
| 汇报这段时间做了什么、结果如何 | 经营回顾 |
| 讲成果、讲产品、讲新能力 | 产品发布 |
| 要说服人认同一个观点 | 叙事主题演讲 |
| 培训、教学、课件 | 工作坊教学 |
| 融资、对外讲故事 | 投资人路演 |
| 讲原理、讲架构 | 技术深潜 |
| 出了问题要复盘 | 故障复盘 |
| 要 PPT 文件 / 在 Office 里改 | 骨架照选，交付形态改走 4.5（自己写页 + 引擎转换） |

## 四、怎么在流程里用

1. **Step 1 收料**：表达方法选一个（**筛 2–3 个弹卡片**，见「一之二」）；视觉皮在 `../visual-library/` 里另选一个（**Step 4 才问，先开选型页给用户**，J-56）。
2. **Step 2 出大纲**：用**表达方法**的论证顺序组织主线与页序；用它的**证据要求**筛掉撑不住结论的素材（见 J-05 抓大放小）。
3. **Step 3 出逐页**：用它的**页序与页型词汇**决定每页的 Action Title 与页面内容。
4. **Step 4 出页面**：**视觉皮**落地成 HTML；走 PPTX 路线时自己按方法 id 对应的 `specs/<id>/` 写页（id 只在内部用，对用户仍报中文名）。

**只借方法，不搬字段。** `ppt-master` 的 spec 有它自己的一套契约（`design_spec.md` 的 I–VII 节、Mode/Visual Style 引用、Master/Layout 槽位），那是它的内部格式。**不要**把那些字段写进我们的《大纲》《逐页内容》两份 HTML，只取「论证怎么排」这一层。

**风格规格在哪**：本目录 14 种的规格在 `specs/<id>/templates/design_spec.md`（英文；Best Fit、页型词汇、证据纪律、视觉默认、评审焦点）。需要细化某个方法的页序或证据要求时再读对应 spec，**不要通读 14 份**。

---

## 五、加新表达方法的规矩

1. 写 `<id>.md`，至少包含：适合场合、一句话内核、论证顺序、页序、证据要求、语气。
2. 在本文档 §1 加一行，并在 §3 选型速查里补对应场景。
3. 不要把新方法塞进旧方法的 md 里——一个文件只管一个方法。
