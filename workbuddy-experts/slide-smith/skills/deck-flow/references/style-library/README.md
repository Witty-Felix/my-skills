# 表达方法库

**这一层只管「怎么论证」**：论证顺序、页序、证据要求、页面角色词汇、语气。
它**不管**长什么样——配色、字体、版式语法在 `../visual-library/`（视觉风格）。

两者正交，可任意组合。只借方法，不搬字段。

---

## 一、14 种

| id | 名称 | 适合什么场合 | 一句话内核 |
|---|---|---|---|
| `mbb-consulting` | MBB 战略咨询 | 战略文件、董事会/管理层决策材料 | 结论先行 + 文档级信息密度，编号图表、页脚出处 |
| `consulting-decision` | 决策咨询 | 要给结论、要证据支撑的决策文档 | 答案先行、证据驱动，视觉克制 |
| `investor-pitch` | 投资人路演 | 融资路演、BP | 用证据而非形容词，带投资人走完「为什么是现在」到「为什么是这团队」 |
| `operating-review` | 经营回顾 | 周期性经营会、业务复盘 | 结果 / 差异 / 原因 / 责任承诺四段拆开，不粉饰难看的数字 |
| `incident-postmortem` | 故障复盘 | 事故复盘、可靠性建设 | 无责化重建时间线，区分促成因素与责任，落到可验证的行动 |
| `product-launch` | 产品发布 | 新品发布、能力宣讲 | 价值先行：每个能力主张先被一个可演示的时刻兑现，再命名 |
| `solution-proposal` | 方案提案 | 客户提案、投标、售前 | 先证明你懂我的处境，再用具体且有成本的方案赢下这份工作 |
| `technical-deepdive` | 技术深潜 | 架构讲解、技术评审 | 机制优先：每个主张落在约束、取舍和可观测行为上 |
| `academic-research` | 学术研究 | 论文答辩、研究汇报 | 从问题、方法、结果构造可辩护的主张，并让局限始终可见 |
| `science-explainer` | 科普讲解 | 对外科普、公众传播 | 从熟悉的大地出发，用视觉类比建立理解，不为易懂牺牲准确 |
| `narrative-keynote` | 叙事主题演讲 | 大会演讲、发布会主旨、争取认同 | 用张力、转折和具体的人物细节，把一个观点讲到能被接受 |
| `workshop-teaching` | 工作坊教学 | 培训课件、内训、带练 | 目标 → 示范 → 练习 → 诚实的检验，序贯推进理解 |
| `creative-pitch` | 创意提案 | 创意方案、品牌 campaign | 把一个真实洞察落地，并展示它如何活在每个出现的地方 |
| `duty-manual` | 制度手册 | 规则汇编、作业手册 | 把散落的规则收拢到一条判断轴上，机制先于规则，每条可追溯到机制页 |

> **视觉皮不在这里。** 共 19 种视觉风格（18 种 catalog + 本包自带的 `pop-collage`），见 `../visual-library/README.md`。

## 二、「表达」和「视觉」的区别

- **表达**（本目录 14 种）决定**怎么论证**：论证顺序、页序、证据要求、语气。
- **视觉**（`../visual-library/`）决定**长什么样**：配色、字体、版式语法、页面原型、质感。

**「MBB 咨询的论证骨架 + 波普拼贴的视觉皮肤」是成立的**——先按 MBB 排主线和页序，再用选定的皮落地。

如果用户分不清，就问一句：「更想要好看的皮，还是更想要会说服人的讲法」，或者按场合直接推荐。

## 三、选型速查

| 用户说 | 选 |
|---|---|
| 给领导看 / 要下结论 | `mbb-consulting` 或 `consulting-decision` |
| 汇报这段时间做了什么、结果如何 | `operating-review` |
| 讲成果、讲产品、讲新能力 | `product-launch` |
| 要说服人认同一个观点 | `narrative-keynote` |
| 培训、教学、课件 | `workshop-teaching` |
| 融资、对外讲故事 | `investor-pitch` |
| 讲原理、讲架构 | `technical-deepdive` |
| 出了问题要复盘 | `incident-postmortem` |
| 要 PPT 文件 / 在 Office 里改 | 骨架照选，交付形态改走 4.4（自己写页 + 引擎转换） |

## 四、怎么在流程里用

1. **Step 1 收料**：表达方法选一个；视觉皮在 `../visual-library/` 里另选一个（两边各一个）。
2. **Step 2 出大纲**：用**表达方法**的论证顺序组织主线与页序；用它的**证据要求**筛掉撑不住结论的素材（见 J-05 抓大放小）。
3. **Step 3 出逐页**：用它的**页序与页型词汇**决定每页的 Action Title 与页面内容。
4. **Step 4 出页面**：**视觉皮**落地成 HTML；走 PPTX 路线时把表达方法 id 交给 `ppt-master` 的同名 style workspace。

**只借方法，不搬字段。** `ppt-master` 的 spec 有它自己的一套契约（`design_spec.md` 的 I–VII 节、Mode/Visual Style 引用、Master/Layout 槽位），那是它的内部格式。**不要**把那些字段写进我们的《大纲》《逐页内容》两份 HTML，只取「论证怎么排」这一层。

**风格规格在哪**：本目录 14 种的规格在 `specs/<id>/templates/design_spec.md`（英文；Best Fit、页型词汇、证据纪律、视觉默认、评审焦点）。需要细化某个方法的页序或证据要求时再读对应 spec，**不要通读 14 份**。

---

## 五、加新表达方法的规矩

1. 写 `<id>.md`，至少包含：适合场合、一句话内核、论证顺序、页序、证据要求、语气。
2. 在本文档 §1 加一行，并在 §3 选型速查里补对应场景。
3. 不要把新方法塞进旧方法的 md 里——一个文件只管一个方法。
