# 视觉风格库

**这一层只管「长什么样」**：形状语言、装饰密度、留白节奏、字体性格、质感与抬升。
它**不管**论证怎么排、页序怎么走、证据要多硬——那是 `../style-library/`（表达方法）的事。

两者正交，可任意组合：`operating-review` 的骨架 + 深色科技的皮，或者 `mbb-consulting` 的骨架 + 波普拼贴的皮。

> **风格一律用中文名。** 下面表格的「风格」列是正式称呼，跟用户沟通只报中文名，不报英文 id。英文 id 只作文件名（`<id>.md`）与内部标识用，**不改名**——改了会断掉 `deckcore` 的引用。

> **「白底圆角卡片页」不在这里。** 那是 Step 3《逐页内容》这个交付物本身的固定形态（见 `SKILL.md` 3.2 与 `templates/逐页内容模板.html`），不是一种可选风格，也不参与 Step 4 的风格选择。别把它算进这 22 种。

## 二、怎么选

1. **先定场合，再定气质。** 给谁看、在哪放、投影还是打印，决定能承受多少密度与装饰。
2. **不要按「好看」选，按「该让听众感到什么」选。** 要稳 → 瑞士极简 / 杂志编辑；要未来感 → 深色科技 / 毛玻璃；要温度 → 波普拼贴 / 剪纸层叠 / 手绘笔记。
3. **一层只选一个皮。** 一份稿子只允许一套视觉语法，混用会像出自不同的人手。
4. **没指定就问一句。** 别问成考卷——一次问完，用户说「你定」就按场合最贴的选，默认回落波普拼贴。
5. **不换皮也是合法答案。** 用户说「就这样 / 不用换」→ 直接用 Step 3 那份白底圆角卡片，只做排版精修，不强行套任何皮。

### 组合规则

- 皮与骨架**各选一个**，互不影响。
- 走 PPTX 时**不交给任何人**：自己按这份皮的规格写 SVG，表达方法决定页序；引擎只做校验与转换。
- 用户要一个库里没有的皮 → 明说没有，请他给参考（截图 / 网站 / 现有 HTML），**不要现编**。

## 三、逐页生图时，风格怎么进 prompt

选定的皮要拆成 prompt 的四个要素，**每页只改「画什么」，不改「怎么画」**——否则 15 页会像出自不同的人手。

| 要素 | 从风格的哪来 | 例子（波普拼贴） |
|---|---|---|
| 质感 | 调性 | 波普拼贴、剪贴杂志感、贴纸感、有点吵 |
| 色板 | 色板那几个变量 | 奶油底 + 橙 / 钴蓝 / 黄，统一 3px 墨黑描边 |
| 图形语法 | 视觉语法 | 粗描边、硬投影、轻微旋转、半调网点 |
| 构图密度 | 安全区与页面原型 | 大标题占半版，留白大，不塞满 |

**文字不写进 prompt。** 生图只出视觉，页面上要读的字必须是原生文本框（见 J-18）。

## 四、加新视觉皮的规矩

1. 必须有一份**真实跑通的 HTML**（不是描述），命名为 `<id>.reference.html`。
2. 写 `<id>.md`，至少包含：调性、色板、字号阶、视觉语法、安全区、组件清单、页面原型、交互、坑。
3. **必须遵守 `_style-contract.md`**：E 层 7 个变量一个不少、S/F 层带 `<id>-` 前缀、私有类带 `<id>-` 前缀、资产进 `<id>/assets/`、字体只写获取方式。
4. 在本文档 §1.1 加一行（**风格列写中文名**）；若属于 catalog 家族，则在 `deckcore/references/visual-styles/_index.md` 登记。
5. 不要把新皮塞进旧皮的 md 里——一个文件只管一个皮；也不要把旧皮的资产挪来复用（契约 §三 第 5 条）。
