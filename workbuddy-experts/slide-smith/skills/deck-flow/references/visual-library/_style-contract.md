# 视觉风格契约（Style Contract）

> 本文件是**所有视觉皮必须遵守的机制约定**，2026-10-24 起生效。
> 起因：pop-collage（包内原创，全规格带 HEX）与 18 种 catalog 皮（不定义 HEX）两套契约并存，
> 资产/字体无隔离、CSS 变量无命名空间、引擎骨架与皮耦合。本契约补齐这四层。
> 新皮**必须**按本契约落地；存量皮迁移为待办（见文末）。

---

## 一、三层变量分层（token schema）

每份皮的 reference.html 的 `:root` 必须按三层组织，**禁止混层**：

```css
:root{
  /* ── E 层 · 引擎契约（固定名，所有皮同名同义，引擎依赖它们） ── */
  --e-stage-w:1280px;          /* 舞台宽，固定 */
  --e-stage-h:720px;           /* 舞台高，固定 */
  --e-font-ui:"Noto Sans SC",sans-serif;  /* HUD/讲稿抽屉 UI 字体 */
  --e-hud-fg:#eee;             /* HUD 前景 */
  --e-hud-accent:#F6C25E;      /* HUD 进度条/按钮 hover 强调（取自风格主强调色） */
  --e-stage-bg:#111;           /* 舞台底色：html/body 背景，破底页与 HUD 底片依赖 */
  --e-notes-bg:#111;           /* 讲稿抽屉底色 */

  /* ── S 层 · 风格色板（强制 <id>- 前缀，<id>=风格目录名） ── */
  --ag-gold:#F6C25E;           /* 以 award-gold 为例 */
  --ag-ink:#0a0a0a;
  /* ... */

  /* ── F 层 · 字体栈（强制 <id>- 前缀） ── */
  --ag-font-display:"庞门正道粗书体",serif;
  --ag-font-body:"阿里妈妈数黑体",sans-serif;
}
```

规则：
1. **E 层**：名字固定、跨皮同名，引擎脚本与 HUD 只读 E 层。每份皮必须提供全部 E 层变量，一个不能少。
   当前清单共 **7 个**：`--e-stage-w` / `--e-stage-h` / `--e-font-ui` / `--e-hud-fg` / `--e-hud-accent` / `--e-stage-bg` / `--e-notes-bg`。
   `award-gold` / `cartoon-mascot` 已齐全；`pop-collage` 为存量皮，未定义 E 层，属迁移待办（见文末），**不算合规**。
2. **S/F 层**：必须带 `<id>-` 前缀。通用词（`--ink`、`--paper`、`--accent`）**禁止裸用**——撞名即跨皮污染。
3. 风格 CSS 里的颜色一律引用 S 层变量，**组件规则里不写裸 HEX**。HEX 的唯一合法出现位置：① E/S 层变量定义处；② @font-face 的 src；③ 图片路径。
4. **引擎结构类（.hud*、.notes*、html/body 等）只读 E 层（`--e-*`）**，禁止引用 S 层变量——引用了就是引擎→皮的逆向耦合（2026-10-24 复查发现的漏网项，award-gold 的 `.notes b` 曾用 `--ag-gold`，已修）。

## 二、类名隔离

- **结构类是引擎公共契约，所有皮同名**：`#stage`、`.slide`、`.is-active`、`.hd`、`.kick`、`.ttl`、`.note`、`.r` / `.rf`（入场动效）、`.hud*`、`.notes*`。皮**不得改它们的布局语义**（定位/尺寸/层级），只允许通过 S/E 层变量改外观。
- **风格私有类必须带 `<id>-` 前缀**（如 `.ag-photo`、`.ag-names`），否则跨皮复制页面时必然冲突。
- 新增样式只能追加在 `<style>` 末尾且带前缀——这条从"人工约定"升级为自检项（见 §五）。

## 三、资产与字体目录（per-style 隔离）

```
visual-library/
├── _style-contract.md          ← 本文件
├── README.md                   ← 索引
├── <id>.md                     ← 风格规格（按 §四模板）
├── <id>.reference.html         ← 参考实现（相对路径引 <id>/ 下的资产）
└── <id>/
    ├── assets/                 ← 本皮专属图片，文件名带 <id>- 前缀
    └── fonts/                  ← 本皮专属字体（woff2 优先，ttf 兜底；注明许可证）
```

规则：
1. **新皮资产一律进 `<id>/` 子目录**，禁止放共享 `assets/` 平铺区。
2. 字体必须注明许可证状态（免费商用 / 付费仅本机）。付费字体不进包，写获取方式。
3. reference.html 内引用一律**相对路径**，禁止第三方图床。
4. 存量迁移待办：pop-collage 的 `assets/` 平铺区应迁为 `pop-collage/assets/`，迁移前 README 必须标注"共享区已冻结，仅供 pop-collage"。

## 四、规格文档模板（`<id>.md` 必含九节）

```markdown
# <id> · <中文名>
参考实现：<id>.reference.html（N 屏，内容虚构脱敏）
## 1 调性          （一句话内核 + 不适合场合）
## 2 色板          （S 层变量表 + 用法约束）
## 3 字体          （F 层变量表 + 许可证状态 + 获取方式）
## 4 字号阶        （表：用途/字号/备注）
## 5 视觉语法      （构图/装饰/质感规则，含 CSS 配方）
## 6 安全区与栅格  （边距、文字区比例、文图分区规则）
## 7 组件清单      （风格私有类逐个说明）
## 8 页面原型      （表：原型名 → 结构 → 适用内容；每原型在 reference 里至少 1 屏）
## 9 坑            （本皮特有的翻车点）
```

写完在 `README.md` §1.1 登记一行。**catalog 家族皮**（deckcore 系）仍登记 `_index.md`，且它们天然不满足 §一/§三（不定义 HEX、无资产）——在 README 标注"半规格，需现场补 token"，不强制迁移。

## 六、引擎/皮分层原则

- 引擎（翻页/HUD/讲稿抽屉/`fit()`/`@page`）是**通用件**，随契约维护一份标准实现（当前以 pop-collage.reference.html 的 `<script>` 为准，新皮原样复制 script 与 HUD/notes 结构，只换 E 层变量取值）。
- 皮只提供：E 层取值 + S/F 层变量 + 结构类的外观覆盖 + 风格私有类。
- **未来重构方向**（待办，不阻塞新皮）：把引擎抽为独立 `engine.html`，皮以 token 表注入。
