# HTML PPT 工作流

四个门，三道审核。**跳过任何一个门，这次产出就是废的。**

```
┌─ Step 1 收料 ────────► brief.md        （不用审，问清即可）
├─ Step 2 出大纲 ──────► outline.md      ⛔ 必须等「通过」
├─ Step 3 出逐页 ──────► slidespec.md    ⛔ 必须等「通过」
└─ Step 4 出页面 ──────► <slug>.html     （做完自检，交付）
```

工作目录：`<workspace>/ppt/<slug>/`。四份文件同放一处，永不分散。

---

## Step 0 · 每次开工前必做

1. 读 `references/judgment-library.md`（判断库）。
2. 读 `references/style-library/README.md`（风格索引）。
3. 判断这次是**新建**还是**改已有稿**：
   - 新建 → 从 Step 1 走。
   - 改已有稿 → 先读它现有的 `outline.md` / `slidespec.md`，判断改动落在哪一层，**回到那一层重做**，不要直接改 HTML。

---

## Step 1 · 收料

目标：把「我想做个 PPT」变成一份能开工的 brief。

必问（缺一不可，一次问完，不要分三轮）：

| 项 | 问法 | 为什么必须问 |
|---|---|---|
| 听众 | 给谁看？领导 / 客户 / 团队 / 学员 | 决定详略和语气 |
| 时长 | 讲多久？ | 决定页数（≈ 1.5 分钟/页） |
| 目标 | 听完你希望他们做什么 / 记住什么 | 决定主线，不是「讲完」 |
| 风格 | 用哪个风格？默认 pop-collage | 决定 Step 4 |
| 资料 | 资料在哪？有没有口径要求 | 决定 Step 2 的素材边界 |

产出 `brief.md`，模板见 `templates/brief.md`。

**硬规则**：资料里出现的数字，只要来源不明，就在 brief 里标 `[待确认]`，不许带进大纲。

---

## Step 2 · 出大纲

### 2.1 先过判断库（关键步骤）

不要直接写大纲。先按判断库生成一张**默认处理清单**，交给他确认。

规则：
- 只列**这次资料真会碰到**的条目，最多 6 条。
- 每条写：判断编号 · 一句话结论 · 本次默认怎么做 · 要不要改。
- 他回「都行 / 按默认」就直接走；他改哪条就记哪条。

格式示例：

```
这次会碰到 4 条判断，默认这么处理：

| 编号 | 判断 | 本次默认 |
|---|---|---|
| J-01 | 大纲不写配色 | 遵守 |
| J-03 | 过程细节默认不写 | 课程设计、运营机制不进大纲 |
| J-04 | 长清单不逐条念 | 只挑 3 个代表项目 |
| J-06 | 结构由你定 | 按你上次的两条线结构 |

有要改的直接说。
```

### 2.2 定主线

先写一句话主线（整份 PPT 只允许有一条）：
> 「用 28 天把『学 AI』变成『做 AI』」

主线必须满足：**能被反驳**。不能被反驳的是口号，不是主线。

### 2.3 搭骨架

- 一级结构不超过 **3 块**（超过就说明还没想清）。
- 每块下面 2–4 个小节。
- 每个小节写：**一句结论**（不是标题）+ **支撑它的 2–3 个事实/数据**。

产出 `outline.md`，模板见 `templates/outline.md`。

**⛔ 门禁**：写完就停，把 `outline.md` 的核心结构（不是全文）贴给他，等「通过」。
他没说通过，绝不进入 Step 3。

---

## Step 3 · 出逐页内容

### 3.1 再过一次判断库

粒度变了，判断也要重问。这次重点问：
- 哪些内容**留在这一页**、哪些该单独一页、哪些直接砍掉
- 长清单要不要拆页
- 哪些页需要讲稿、哪些不需要

同样只问碰得到的条目。

### 3.2 拆页

一页一个观点。每页必须写全五件事：

| 字段 | 要求 |
|---|---|
| `#` | 页码，从 00 开始 |
| `Action Title` | **一句结论**，不是名词短语。看到标题就知道这页在说什么 |
| `页面内容` | 真正贴到屏幕上的字。能用表格/清单就不用段落 |
| `版式` | 讲**结构、层级、元素关系**。不写颜色（见 J-01）、不写字体名 |
| `讲稿` | 口头补什么。一句话即可，不写逐字稿 |

页数控制：
- 15 分钟 ≈ 12–16 页
- 25 分钟 ≈ 18–24 页
- 超过 30 页必须有目录页和章节页

节庆页（封面 / 目录 / 章节 / 结尾）单独计数，不算在内容页里。

产出 `slidespec.md`，模板见 `templates/slidespec.md`。

**⛔ 门禁**：写完就停，等「通过」。

---

## Step 4 · 出页面

### 4.1 定风格

从 `references/style-library/` 选一份，读它的 md 规范 + 参考实现。
没有合适的就明说「目前只有 X，要么用 X，要么你先给我一个参考」，**不要现编一套风格**。

### 4.2 写 HTML

按 `references/step4-build.md` 执行。核心约束：

- 固定舞台 `1280×720`，`fit()` 等比缩放，不响应式重排
- 每页一个 `<section class="slide">`，讲稿写 `data-note`
- 键盘 ← → / Space 翻页，`N` 开讲稿，`F` 全屏
- 只引用本地图或已授权直链

### 4.3 自检（交付前必跑）

1. **逐页截图**：无头 Edge，`--window-size=1280,720`，一次 4–6 张，别批量超时。
2. **看图说话**：每张图看三件事——文字有没有溢出、块有没有错位、层级清不清楚。
3. **翻页检查**：首屏、末屏、每个章节页必须点名看过。
4. **外链检查**：不许出现第三方图床域名。

不合格就改，改完重截。**没看过截图不算做完。**

---

## 交付

给三样东西：
1. HTML 文件的绝对路径
2. 一句结构说明（≤100 字）
3. 页数 + 风格 + 讲稿入口说明

需要上线时再问一句「要不要发到资料库」，不要默认发布。

---

## 反向更新（每次收工必做）

他这次如果做了新的取舍（砍了什么、加了什么、换了什么口径），
追加到 `references/judgment-library.md`，格式：

```md
### J-XX · 一句话结论
- 场景：什么时候适用
- 做法：具体怎么处理
- 来源：YYYY-MM-DD 某项目的哪次订正
```

判断库是这份专家越用越准的唯一原因，**别让它荒着**。

风格如果有新增或微调，写进 `references/style-library/<id>.md`，并在 `README.md` 索引里加一行。
