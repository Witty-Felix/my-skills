后续规划 · A · 教学部（上）

PK 赛收官之后，从强制打卡转成按需辅导

01

以 PK 赛为节点，兑现进阶名额

14 位老师四维度展示。比赛本身不是目的，是筛出下一批重点服务对象。

02

培训形式转型

不再要求每日打卡，转为 不定期直播 + 一对一沟通 + 线下辅导。

打卡能拉齐下限，但拉不高上限 —— 所以要换打法。

后续规划 · A · 教学部（下）

从知识库推到工作台，再用奖励把意愿拉起来

03

赋能官落地，从知识库推到工作台

学员管理、考勤、成绩、沟通记录、待办。
路径：单智能体 → 多智能体 → 部门级 AI 系统

04

奖励机制

用顶级模型账号做激励 —— 发的是「用得起」的资格。

注发的是「用得起顶级模型」的资格 —— 比发实物更能让人真的动手试。

后续规划 · B · Vibe Coding

翁锐直播引出 Vibe Engineering：从 0 到 1，到 1 到 N

01

翁锐大佬专场直播

面向社区成员开一场直播，作为课程升级的引子。

02

推出 Vibe Engineering 课程

双重经验叠加：翁锐本人多个真实项目的工程经验 + 近期接触国外最顶尖的大模型、并用它们实际做了大量项目。

03

能力阶梯

Vibe Coding ＝ 0→1，把想法变成能打开的东西；Vibe Engineering ＝ 1→N，把东西做成能长期运行的工程。

后续规划 · C · 星禾AI 社区（上）

做简约的自有 AI 系统，抢的是入口

01

品牌与世界观

统一调性与视觉，走简约克制风格（参考苹果、Claude Code 一类），配套世界观与 IP 设计。

02

搭建专属 AI 系统

不做又一个工具集合，而是多板块可联动的自有系统：以工作台为入口，把知识库、工作流、智能体串起来。

工作台
WORKBENCH
知识库
工作流
智能体

注入口本身就是战略资产 —— 我们要做的不是工具，是入口。

后续规划 · C · 星禾AI 社区（下）

三层演进：个人工具 → 部门系统 → 集团入口

集团 AI 入口全员必用
部门系统教学部 / 私域部共用
个人工具老师自己的知识库与工作台
一线老师参与搭建不是自上而下推
04

组织形态向 AI 原生演进

方向是 AI 主导、人辅助；系统必须由一线老师参与搭建。

05

校区 AI 团队建设

重点推进 西安、武汉、郑州 三个校区先建起来，后续陆续开展更多校区 AI 社区。

收尾

这个月我们证明了一件事 ——
